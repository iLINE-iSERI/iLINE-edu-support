# Firebase 보안 규칙 — 배포용 병합본

> 그뤠잇과 **같은 Firebase 프로젝트**를 쓰므로(D-8), 규칙은 하나로 합쳐서 배포해야 합니다.
> 이 폴더의 두 파일이 **그뤠잇 기존 규칙 + 창의재단 추가분**을 합친 최종본입니다.

---

## ⚠️ 왜 그냥 붙여넣으면 안 되는가

창의재단 레포의 `firestore.rules` / `storage.rules` 는 **창의재단 부분만** 담은 파일입니다.
그것을 콘솔에 그대로 붙여넣으면 **그뤠잇 규칙이 전부 사라져 서비스가 잠깁니다.**

또 두 파일에 같은 이름의 헬퍼 함수가 있어 단순히 이어 붙이면 오류가 납니다.

| 함수 | 그뤠잇 | 창의재단(원본) | 병합본 처리 |
|---|---|---|---|
| `isSignedIn()` | 있음 | 있음 | 그뤠잇 것 **재사용** |
| `isOwner(uid)` | 있음 | 있음 | 그뤠잇 것 **재사용** |
| `isMember()` | — | 있음 | `isSupportMember()` 로 **개명** |
| `isStaff()` | — | 있음 | `isSupportStaff()` 로 **개명** |
| `isUnder20MB()` | 있음(Storage) | `isUnderSizeLimit()` | 그뤠잇 것 **재사용** |

→ 이 폴더의 병합본은 위 처리가 이미 끝난 상태입니다. **함수 중복 없음을 확인했습니다.**

## 적용 방법

### 방법 1 — Firebase 콘솔에서 붙여넣기 (레포 없이 가능)

**Firestore**
1. [Firebase 콘솔](https://console.firebase.google.com) → 프로젝트 선택
2. `빌드 > Firestore Database` → **규칙** 탭
3. **기존 내용을 어딘가에 복사해 백업**해 두세요
4. `firestore.rules` 내용으로 전체 교체 → **게시**

**Storage**
1. `빌드 > Storage` → **규칙** 탭
2. 마찬가지로 백업 후 `storage.rules` 내용으로 교체 → **게시**

### 방법 2 — 그뤠잇 레포에 반영 후 CLI 배포

그뤠잇 레포에 `firebase.json`이 있으므로 그쪽이 규칙 배포를 담당합니다.

```
# 그뤠잇 레포에서
# firestore.rules, storage.rules 를 이 폴더 내용으로 교체 후
firebase deploy --only firestore:rules,storage
```

> 장기적으로는 **방법 2**를 권합니다. 규칙이 코드로 관리되어 변경 이력이 남습니다.

## 적용 후 반드시 확인할 것

규칙은 잘못 건드리면 **운영 중인 그뤠잇이 즉시 멈춥니다.** 게시 후 아래를 확인하세요.

- [ ] 그뤠잇에서 로그인 → 강의 목록이 보이는가
- [ ] 그뤠잇 공지사항·자료실이 열리는가
- [ ] 그뤠잇 관리자 화면이 동작하는가
- [ ] 비로그인 상태에서 그뤠잇 메인의 카테고리가 보이는가

문제가 생기면 백업해 둔 기존 규칙으로 되돌리세요.
