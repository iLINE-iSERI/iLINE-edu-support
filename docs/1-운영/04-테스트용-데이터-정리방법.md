# 테스트용 데이터 정리방법

> 개발·시험 중에 만든 계정과 신청서를 지웁니다.
> **접수 개시 직전에 한 번 더** 하시게 됩니다.

⚠️ **운영이 시작된 뒤에는 이 문서대로 하면 안 됩니다.** 신청 기록은 보존 의무가 있고,
탈퇴는 삭제가 아니라 `status: withdrawn` 으로 처리합니다. 이 문서는 **실데이터가
들어오기 전**에만 쓰는 것입니다.

> 🔴 **접수 개시일에 `scripts/reset-test-data.mjs` 를 저장소에서 뺍니다.**
> 이 도구는 **평상시 담당자 업무용이 아닙니다.** 남겨두면 언젠가 누군가
> 씁니다. 마지막 정리를 마친 그날 지우세요 — 깃 기록에 남으므로 정말
> 필요해지면 되살릴 수 있습니다. (할 일 목록에도 적혀 있습니다)

---

## ⭐ 빠른 방법 — 명령 한 줄 (권장)

다섯 곳을 **순서대로** 정리하는 스크립트를 만들어 두었습니다 (D-51).
아래 「손으로 하는 방법」과 결과가 같고, **빠뜨릴 위험이 없습니다.**

저장소 폴더에서:

```
node scripts/reset-test-data.mjs "C:\경로\서비스계정.json"
```

이렇게만 하면 **아무것도 지우지 않고 목록만** 보여줍니다.
지울 건수와 남길 계정을 눈으로 확인한 뒤,

```
node scripts/reset-test-data.mjs "C:\경로\서비스계정.json" --delete
```

`--delete` 를 붙여도 바로 지우지 않습니다. 화면에서 **`delete` 를 직접
타이핑**해야 진행됩니다. 잠금을 두 겹으로 둔 이유는, 이 명령이 **운영
시작 뒤에 실행되면 안 되는** 종류이기 때문입니다.

**담당자 계정은 자동으로 남습니다** (`role: staff` 인 회원). 다른 계정도
남기시려면 `--keep 이메일@주소` 를 붙이세요. 여러 번 쓸 수 있습니다.

| 옵션 | 뜻 |
|---|---|
| *(없음)* | 목록만 보여주고 끝 |
| `--delete` | 실제로 지움 (타이핑 확인 필요) |
| `--only <이메일>` | **이 사람 것만** 건드림 |
| `--keep-accounts` | 계정·회원 문서는 **한 건도** 안 지움 (기록만 비움) |
| `--keep <이메일>` | 이 계정은 남김 |
| `--all` | ⚠️ 담당자 계정까지 전부 지움 — 권한 부여를 처음부터 다시 해야 합니다 |
| `--programs` | id 가 `test-` 로 시작하는 **공고**도 지움 |

> 📐 **옵션은 지우는 범위를 좁히기만 합니다.** (`--all` · `--programs` 만
> 예외이고, 둘 다 이름이 그렇게 읽힙니다.) 그래서 옵션을 잘못 붙여서
> **더 많이** 지워지는 일은 없습니다.

### 시험 중에 자주 쓰는 조합

| 하고 싶은 일 | 명령 뒤에 붙일 것 |
|---|---|
| 같은 계정으로 **신청을 다시** 해 보고 싶다 | `--only 그이메일 --keep-accounts --delete` |
| 신청 기록만 전부 비우고 **계정은 다 남긴다** | `--keep-accounts --delete` |
| 시험 계정 **한 사람만** 통째로 없앤다 | `--only 그이메일 --delete` |
| 접수 개시 직전 **전체 청소** | `--delete` (담당자는 자동으로 남습니다) |

**가장 자주 쓰시게 될 것은 첫 줄입니다.** 신청서와 중복 신청 열쇠만
지워지므로, 그 계정으로 로그인해 **같은 공고에 다시 신청**할 수 있습니다.
계정을 다시 만들 필요가 없습니다.

> 🔒 서비스 계정 키는 **프로젝트 전체 권한을 가진 마스터키**입니다.
> 저장소 밖에 두시고, 채팅·메일에 붙여 넣지 마세요.
> 키가 어디 있는지 모르시면 `docs/1-운영/03-담당자-권한-부여.md` 를 보세요.

> ⚠️ **구글 시트와 드라이브는 이 스크립트가 건드리지 않습니다.**
> 스프레드시트의 줄과 드라이브 `01_신청` 폴더는 손으로 지우세요.
> 시트를 비우실 때는 **머리글(첫 줄)까지** 지워야 새 머리글이 들어갑니다.

# 손으로 하는 방법 (콘솔)

> 스크립트를 쓸 수 없을 때, 또는 **무엇이 어디에 있는지 알고 싶을 때** 보세요.
> 스크립트가 하는 일도 아래와 정확히 같습니다.

## 0. 먼저 정하실 것 — 담당자 계정은 남기세요

지금 `role: staff` 로 지정한 계정을 지우면 **담당자 권한도 함께 사라집니다.**
다시 가입 → role 변경 → Custom Claims 부여를 처음부터 해야 합니다.

**권장**: 담당자 계정 하나만 남기고, 그 계정의 **신청 기록만** 지웁니다.

---

## 1. 지워야 할 곳이 네 군데입니다

한 사람의 흔적은 네 곳에 나뉘어 있습니다. **하나라도 빠뜨리면 찌꺼기가 남습니다.**

| 순서 | 위치 | 무엇이 있나 |
|---|---|---|
| ① | **Storage** `support/applications/{uid}/` | 신청서 PDF · 첨부 파일 |
| ② | **Firestore** `support_applications` | 신청 문서 |
| ②′ | **Firestore** `support_application_keys` | **중복 신청 잠금** — `{uid}_{programId}` |
| ③ | **Firestore** `support_users/{uid}` | 회원 정보 · 동의 이력 |
| ④ | **Authentication** | 로그인 계정 |

**반드시 이 순서로.** ④(계정)를 먼저 지우면 uid를 알 수 없게 되어
①~③에서 무엇을 지워야 할지 찾기 어려워집니다.

> ⚠️ **②′ 를 빠뜨리면 같은 사람이 다시 신청할 수 없습니다.** 신청서만 지우면
> 화면은 폼을 열어주는데 제출에서 규칙이 거부합니다. 화면 차단(신청서 문서)과
> 규칙 차단(열쇠 문서)이 **서로 다른 지점**이라 둘 다 지워야 합니다.
> *(09-05 실제로 확인)*

> 시트·드라이브에도 사본이 남습니다. 시험 줄과 PDF는 **스프레드시트와
> `01_신청` 폴더에서 따로** 지우세요 — Firebase 를 지워도 사라지지 않습니다.

---

## 2. uid 먼저 적어두기

**Firebase 콘솔 → Authentication → Users**

지울 계정들의 **사용자 UID** 를 메모장에 복사해 두세요. 목록 오른쪽에 있습니다.
이 값이 ①~③에서 폴더·문서를 찾는 열쇠입니다.

---

## 3. ① Storage 파일 지우기

**Storage → 파일 → `support` → `applications`**

uid 이름의 폴더들이 보입니다.

- 계정을 통째로 지울 사람 → **uid 폴더째** 삭제
- 담당자 계정(남길 계정) → 그 폴더 **안의 신청건 폴더들**만 삭제

체크박스 선택 → 위쪽 **휴지통** → 확인.

> 폴더 안에 `신청서.pdf` 와 첨부가 함께 있습니다. 폴더째 지우면 한 번에 사라집니다.

---

## 4. ② 신청 문서 지우기

**Firestore → `support_applications`**

문서 ID가 무작위 문자열이라 눈으로는 구분이 안 됩니다. 문서를 열어
`applicant.name` 또는 `uid` 로 확인하세요.

- 시험 데이터뿐이면 **전부 삭제**해도 됩니다
- 문서 오른쪽 **⋮ → 문서 삭제**
- 컬렉션을 통째로 비우려면 컬렉션 이름 옆 **⋮ → 컬렉션 삭제**

---

## 5. ③ 회원 문서 지우기

**Firestore → `support_users`**

문서 ID가 곧 uid입니다. 2번에서 적어둔 것과 대조해 지우세요.

> **담당자 계정 문서는 지우지 마세요.** `role: staff` 가 여기 들어 있습니다.

---

## 6. ④ 계정 지우기

**Authentication → Users**

지울 계정 오른쪽 **⋮ → 사용자 삭제**. 여러 개면 체크박스로 한 번에 됩니다.

---

## 7. 확인

- [ ] 남긴 담당자 계정으로 로그인 → **마이페이지에 신청 내역이 비어 있다**
- [ ] **담당자 화면**에 신청 건이 없다
- [ ] 헤더에 **"신청 관리"** 가 그대로 보인다 *(보이지 않으면 회원 문서를 잘못 지운 것)*
- [ ] Storage `support/applications/` 아래에 남은 폴더가 없다

---

## 자주 빠뜨리는 것

| 빠뜨리면 | 증상 |
|---|---|
| Storage 파일 | 화면에는 안 보이는데 용량과 개인정보가 남습니다 |
| 회원 문서 | 계정만 지우면 **주인 없는 회원 문서**가 남아 담당자 화면에 유령처럼 보입니다 |
| 계정 | 회원 문서만 지우면, 그 사람이 다시 로그인했을 때 "가입 2단계 미완료" 상태가 됩니다 |

---

## 참고 — 사이트에서는 삭제가 안 됩니다

보안 규칙에 `allow delete: if false` 로 막아두었습니다(보존 의무).
지우는 일은 **콘솔에서 사람이 직접** 해야 하고, 그건 의도된 설계입니다.
