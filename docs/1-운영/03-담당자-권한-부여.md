# 담당자 권한 부여하기

> 담당자 화면(「관리」)은 **아무에게도 열려 있지 않은 상태로 시작합니다.** 의도된 초기값입니다.
> 권한을 준 계정에만 헤더에 「관리」 메뉴가 나타납니다.

## 순서 — 세 가지를 다 해야 "전부 다 할 수 있는" 담당자입니다

| | 무엇을 할 수 있게 되나 | 어떻게 |
|---|---|---|
| **①② 사이트 권한** | 「관리」 화면 전부 + 첨부 파일·신청서 PDF·영수증 열람 | 아래 명령 **한 번** (09-18부터 둘을 한꺼번에) |
| **③ 구글 공유** | 시트·공유 드라이브 열람 | 시트 「공유」 + 공유 드라이브 「멤버 관리」에 그 사람 구글 계정 초대 |

①②만 주면 시트를 못 보고, ③만 주면 사이트에서 아무것도 못 합니다. 셋 다 해야 합니다.

---

## ①② 사이트 권한 — 명령 한 번

**준비**: 그 사람이 사이트에서 **회원가입 2단계(참여 정보)까지** 마쳐야 합니다. 실제로 받는
이메일로 가입하게 하세요 — 비밀번호를 잊으면 그 주소로만 복구됩니다.

저장소 폴더(`iLINE-edu-support`)에서 명령창을 열고:

```
node scripts/grant-staff.mjs --env 담당자이메일@example.com
```

`--env` 는 `.env.local` 에 이미 있는 서비스 계정 값을 씁니다 — **키 파일을 새로 만들지 마세요**
(키가 둘이 되고, 옛 키를 지우면 Vercel 의 시트 연동이 멈춥니다). 키 파일이 따로 있으면
`node scripts/grant-staff.mjs D:\keys\서비스계정.json 이메일` 로도 됩니다.

성공하면:

```
🔑 .env.local 의 서비스 계정을 씁니다: …@…iam.gserviceaccount.com
✅ 담당자 권한을 부여했습니다: 담당자이메일@example.com  (role → staff · 첨부 열람 권한)
   해당 계정은 로그아웃 뒤 다시 로그인해야 적용됩니다.
```

이 명령이 하는 두 가지:
- **Firestore** `support_users/{uid}.role` 을 `applicant` → `staff` — 사이트 「관리」 메뉴·화면
- **Custom Claims** `supportStaff: true` — Storage 의 첨부 파일·PDF 열람. Storage 보안 규칙은
  Firestore 를 읽지 못해서 로그인 토큰에 따로 표시를 심어야 합니다

### ⚠️ 다시 로그인해야 적용됩니다

둘 다 **로그인 토큰**에 실리는 값이라, 이미 로그인해 있는 사람에게는 바로 반영되지 않습니다.
**로그아웃 → 다시 로그인** 하면 「관리」가 뜹니다.

### 콘솔에서 손으로 할 때 (비상용)

명령이 안 돌면 Firebase 콘솔 → Firestore → `support_users` → 그 사람 문서(`email` 로 찾기) →
`role` 을 `staff` 로. 이러면 「관리」는 열리지만 **첨부 파일은 안 열립니다** — 그건 명령으로만 됩니다.

## ③ 구글 시트·드라이브 — 별개입니다

서비스 계정을 시트·드라이브에 초대한 것은 **우리 서버가 쓰기 위한 것**이지, 담당자에게
권한을 나눠주는 것이 아닙니다. **담당자의 구글 계정을 따로 초대**해야 합니다.

- 스프레드시트 → 「공유」 → 담당자 구글 계정 (편집자)
- 공유 드라이브 → 「멤버 관리」 → 담당자 구글 계정

사이트 가입 이메일이 구글 계정이 아니면(예: 대학 메일), 시트용 구글 계정을 따로 물어보세요.

## 🧪 테스트 계정 — 담당자 권한과 **다른 것**입니다 (D-111 · 09-26)

비공개 공고에 **시험 신청**을 해 보기 위한 계정입니다. 담당자 권한은 없습니다.

```
node scripts/grant-tester.mjs --env <이메일>            ← 테스트 계정으로
node scripts/grant-tester.mjs --env <이메일> --revoke   ← 일반 회원으로 되돌리기
```

| | 담당자 (`grant-staff`) | 테스트 계정 (`grant-tester`) |
|---|---|---|
| 담당자 화면 | 들어감 | **못 들어감** |
| 비공개 공고 | 보기만 | 보기 + **신청·산출물 제출** |
| 낸 것이 시트·드라이브로 | — | **가지 않음** (담당자 목록에 「시험」) |
| 첨부 열람 권한 | 줌 | **안 줌** |
| 시트·드라이브 공유 | 따로 해야 함 | 필요 없음 |

- 🔴 **담당자 계정은 테스트 계정이 될 수 없습니다.** `role` 이 하나뿐이라 바꾸면 담당자 권한이
  사라집니다 — 도구가 알아서 멈춥니다. 테스트용 계정을 **따로** 만드세요
- 스스로 테스트 계정이 될 수는 없습니다(가입 때 규칙이 일반 회원으로 고정)
- 새로고침하면 바로 적용됩니다(담당자처럼 다시 로그인할 필요 없음)

## 🔴 회수할 때 — 세 곳을 모두

```
①② node scripts/grant-staff.mjs --env 이메일 --revoke     (role → applicant · 첨부 권한 삭제)
③  시트 「공유」·공유 드라이브 「멤버 관리」에서 그 계정 제거   ← 가장 잘 잊습니다
```

**③을 빠뜨리면 사이트에서는 막혔는데 시트로는 학생 개인정보를 계속 봅니다.**
