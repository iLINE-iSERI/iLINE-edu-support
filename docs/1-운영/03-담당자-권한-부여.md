# 담당자 권한 부여하기

> 담당자 화면(「관리」)은 **아무에게도 열려 있지 않은 상태로 시작합니다.** 의도된 초기값입니다.
> 권한을 준 계정에만 헤더에 「관리」 메뉴가 나타납니다.
>
> 📌 **10-02 (D-120) 부터 담당자 지정·회수는 사이트 화면에서 합니다** — 이미 담당자인 사람이
> 「관리 → 회원 관리」에서. 명령(`grant-staff.mjs`)은 **비상용**입니다(로그인할 수 있는 담당자가
> 아무도 없을 때). 예전에는 서비스 계정 키가 있는 사람(개발하는 sunbell)만 할 수 있었습니다.

## 순서 — 세 가지를 다 해야 "전부 다 할 수 있는" 담당자입니다

| | 무엇을 할 수 있게 되나 | 어떻게 |
|---|---|---|
| **①② 사이트 권한** | 「관리」 화면 전부 + 첨부 파일·신청서 PDF·영수증 열람 | **회원 관리 화면에서 [담당자로 지정]** — 둘이 한꺼번에 |
| **③ 구글 공유** | 시트·공유 드라이브 열람 | 시트 「공유」 + 공유 드라이브 「멤버 관리」에 그 사람 구글 계정 초대 — **사람이 직접** |

①②만 주면 시트를 못 보고, ③만 주면 사이트에서 아무것도 못 합니다. 셋 다 해야 합니다.
**사이트는 시트·드라이브에 사람을 넣거나 빼지 않습니다** — 화면에서 지정·회수해도 ③은 그대로입니다.

---

## ①② 사이트 권한 — 회원 관리 화면에서

**준비**: 그 사람이 사이트에서 **회원가입 2단계(참여 정보)까지** 마쳐야 합니다. 실제로 받는
이메일로 가입하게 하세요 — 비밀번호를 잊으면 그 주소로만 복구됩니다. 이메일·비밀번호로 가입했다면
**이메일 인증**까지 마쳐야 지정됩니다(「회원정보 수정」의 이메일 칸 아래 [인증 메일 보내기] — 메일이
스팸함으로 갈 수 있음). 구글로 가입한 계정은 처음부터 인증되어 있습니다.

1. 담당자 계정으로 헤더 **[관리]** → 머리말 위 관리 줄의 **[회원]**
2. 찾기 칸에 그 사람 이름이나 이메일 → 그 줄을 눌러 펼침
3. 맨 아래 **「담당자 권한」 → [담당자로 지정]**
4. 무엇이 달라지는지 읽고 **사유**를 한 줄 적음(필수 · 200자까지 — 예: 「10월부터 정산 담당 합류」)
   → [담당자로 지정]
5. 초록 안내가 뜨면 끝입니다. 그 사람이 사이트를 **새로고침**하면 「관리」가 보이고 첨부 파일도 열립니다
   (10-01 까지는 로그아웃 뒤 다시 로그인해야 했습니다)
6. 시트·드라이브도 봐야 하는 사람이면 아래 ③

### 사이트가 막는 것

화면이 버튼을 감추거나, 눌렀을 때 빨간 글씨로 거절합니다. **서버가 다시 확인**하므로 화면을 우회해도
막힙니다.

| 막는 것 | 왜 |
|---|---|
| **이메일 인증이 안 된 계정** | 담당자는 모든 신청자의 개인정보를 봅니다 — 주소의 주인이 확인되지 않은 계정에는 줄 수 없습니다(10-02 sunbell) |
| 테스트 계정 | 시험용으로 만든 계정입니다. 실제로 쓰는 계정으로 지정하세요 |
| 탈퇴한 회원 | — |
| **본인 권한 회수** | 다른 담당자가 합니다. 그래서 **담당자가 0명이 되는 일**이 생기지 않습니다 |
| 사유가 빈 것 | 기록에 「왜」가 남아야 합니다 |
| 담당자가 아닌 사람의 요청 | 로그인 표시와 회원 문서 **둘 다** 담당자여야 합니다(회수된 사람의 로그인 표시는 최대 1시간 남아서) |

### 기록이 남습니다

지정·회수할 때마다 그 회원 줄의 「담당자 권한」 아래에 **언제 · 무엇에서 무엇으로 · 누가 · 사유**가
남습니다(Firestore `support_role_changes`). **담당자도 고치거나 지울 수 없습니다** — 규칙이 브라우저의
쓰기를 모두 막습니다. 예전처럼 따로 적어 둘 필요가 없습니다.

- 실수로 지정했다가 바로 회수해도 **두 줄 다 남습니다.** 지우지 않는 것이 맞습니다 — 실수와 그 회수가
  함께 남는 것이 기록이 하는 일입니다
- ⚠️ **Firebase 콘솔에서 손으로 바꾼 것은 기록에 남지 않습니다.** 콘솔과 서비스 계정 키는 규칙을
  거치지 않아 기록까지 고칠 수 있습니다 — 콘솔에 들어갈 수 있는 계정을 적게 두는 것으로 지킵니다
- 시트·드라이브 공유(③)를 넣고 뺀 것은 사이트가 모르니 그것만 따로 챙기세요

### 이 화면(과 비상용 명령)이 바꾸는 두 가지

- **Firestore** `support_users/{uid}.role` 을 `applicant` ↔ `staff` — 사이트 「관리」 메뉴·화면
- **Custom Claims** `supportStaff: true` — Storage 의 첨부 파일·PDF 열람. Storage 보안 규칙은
  Firestore 를 읽지 못해서 로그인 토큰에 따로 표시를 심어야 합니다

둘 다 로그인 토큰에 실리는 값이라, 사이트를 열 때 둘이 어긋나 있으면 사이트가 토큰을 새로 받습니다 —
그래서 **새로고침만 하면** 적용됩니다.

## 🆘 비상용 — 명령으로 (로그인할 수 있는 담당자가 아무도 없을 때)

서비스 계정 키(`.env.local`)가 있는 PC 의 저장소 폴더(`iLINE-edu-support`)에서 명령창을 열고:

```
node scripts/grant-staff.mjs --env 담당자이메일@example.com --reason "사유"
```

`--env` 는 `.env.local` 에 이미 있는 서비스 계정 값을 씁니다 — **키 파일을 새로 만들지 마세요**
(키가 둘이 되고, 옛 키를 지우면 Vercel 의 시트 연동이 멈춥니다). 키 파일이 따로 있으면
`node scripts/grant-staff.mjs D:\keys\서비스계정.json 이메일 --reason "사유"` 로도 됩니다.

성공하면:

```
🔑 .env.local 의 서비스 계정을 씁니다: …@…iam.gserviceaccount.com
✅ 담당자 권한을 부여했습니다: 담당자이메일@example.com  (role → staff · 첨부 열람 권한)
   기록에 남겼습니다 (사유: …)
   해당 계정은 사이트를 새로고침하면 적용됩니다.
```

- 화면과 같이 **사유가 필수**이고, 역할이 바뀌면 같은 기록에 「관리 도구」로 남습니다
- 화면의 막음(이메일 인증 · 본인 회수)은 **없습니다** — 비상용이라서입니다. 인증 안 된 계정이면 경고만 합니다
- 회수는 끝에 `--revoke`

### 콘솔에서 손으로 할 때 (최후의 수단)

명령도 안 돌면 Firebase 콘솔 → Firestore → `support_users` → 그 사람 문서(`email` 로 찾기) →
`role` 을 `staff` 로. 이러면 「관리」는 열리지만 **첨부 파일은 안 열리고, 기록에도 남지 않습니다.**

## ③ 구글 시트·드라이브 — 별개입니다

서비스 계정을 시트·드라이브에 초대한 것은 **우리 서버가 쓰기 위한 것**이지, 담당자에게
권한을 나눠주는 것이 아닙니다. **담당자의 구글 계정을 따로 초대**해야 합니다.

- 스프레드시트 → 「공유」 → 담당자 구글 계정 (편집자)
- 공유 드라이브 → 「멤버 관리」 → 담당자 구글 계정

사이트 가입 이메일이 구글 계정이 아니면(예: 대학 메일), 시트용 구글 계정을 따로 물어보세요.

> ⚠️ **공유 목록의 `firebase-adminsdk-…@….iam.gserviceaccount.com` 은 사이트 서버입니다 — 빼지 마세요.**
> 사람이 아니라 사이트가 신청서 PDF·증빙서류를 드라이브에 올리고 시트에 줄을 쓰는 계정입니다(공유
> 드라이브에서는 「콘텐츠 관리자」 — 파일을 올리고 뺀 파일을 휴지통으로 옮겨야 해서). 빼면 그 순간부터
> 드라이브·시트 반영이 멈추고 담당자 화면에 「반영 실패」가 뜹니다. *(10-02 멤버 목록을 보다 나온 질문)*

## 🧪 테스트 계정 — 담당자 권한과 **다른 것**입니다 (D-111 · 09-26)

비공개 공고에 **시험 신청**을 해 보기 위한 계정입니다. 담당자 권한은 없습니다.
화면(회원 관리)에서 지정하는 것은 **보류**했습니다(10-02 sunbell) — 지금처럼 명령으로 합니다.

```
node scripts/grant-tester.mjs --env <이메일>            ← 테스트 계정으로
node scripts/grant-tester.mjs --env <이메일> --revoke   ← 일반 회원으로 되돌리기
```

| | 담당자 (회원 관리 화면) | 테스트 계정 (`grant-tester`) |
|---|---|---|
| 담당자 화면 | 들어감 | **못 들어감** |
| 비공개 공고 | 보기만 | 보기 + **신청·산출물 제출** |
| 낸 것이 시트·드라이브로 | — | **가지 않음** (담당자 목록에 「시험」) |
| 첨부 열람 권한 | 줌 | **안 줌** |
| 시트·드라이브 공유 | 따로 해야 함 | 필요 없음 |
| 지정 기록 | 남음 | 남지 않음 |

- 🔴 **담당자 계정은 테스트 계정이 될 수 없습니다.** `role` 이 하나뿐이라 바꾸면 담당자 권한이
  사라집니다 — 도구가 알아서 멈춥니다. 테스트용 계정을 **따로** 만드세요. 거꾸로 테스트 계정을
  담당자로 지정하는 것도 화면이 막습니다
- 스스로 테스트 계정이 될 수는 없습니다(가입 때 규칙이 일반 회원으로 고정)
- 새로고침하면 바로 적용됩니다
- **여러 개 지정해도 됩니다.** 2인 1팀 공고라면 두 계정이 **같은 팀명**으로 신청해 보면 산출물이
  팀으로 묶이는지까지 시험할 수 있습니다
- 콘솔에서 `support_users` 문서의 `role` 을 `tester`(소문자)로 바꿔도 결과는 같습니다 — 도구는
  그 한 칸을 바꾸기 전에 **계정 찾기·담당자 계정 막기**를 해 줄 뿐입니다
- 시험용 계정을 새로 만들 때 Gmail 이면 주소 뒤에 `+`를 붙여(`아이디+test2@gmail.com`) 얼마든지 만들 수
  있습니다 — 메일은 원래 받은편지함으로 옵니다. 회원 문서만 지운 계정은 같은 주소로 다시 가입할 수 없고
  (「이미 가입된 계정 — 로그인」) 로그인하면 2단계만 다시 받습니다(10-02 확인 · 계정까지 지우는 법은
  `04-테스트용-데이터-정리방법.md` §5·§6)

### 테스트 계정을 되돌리거나 지울 때

| 한 것 | 그 계정이 **이미 낸** 시험 신청 | 그 뒤 **새로** 낸 것 |
|---|---|---|
| 일반 회원으로 되돌림(`--revoke`) | **계속 「시험」** — 시트로 가지 않습니다 | 평소대로 시트로 갑니다 |
| 계정 삭제 | **계속 「시험」** — 시트로 가지 않습니다 | (계정이 없음) |

- **한 번 「시험」으로 표시된 문서는 계정이 바뀌어도 시험으로 남습니다**(D-111). 담당자가 나중에 그
  신청의 상태를 바꿔도 시트로 새지 않습니다
- 시험 신청은 담당자 목록에 **「시험」 배지**를 단 채 남아 있습니다. 그대로 두셔도 됩니다 —
  시트에 없고, 학생에게 안 보입니다. 꼭 치우려면 `04-테스트용-데이터-정리방법.md` 의 콘솔 절차
- 시험 공고는 비공개로 두면 학생에게 안 보입니다(운영 매뉴얼 §3-5)

## 🔴 회수할 때 — 두 곳을 모두

```
①② 회원 관리 → 그 사람 펼치기 → 「담당자 권한」 → [담당자 권한 회수] (사유 필수)
③  시트 「공유」·공유 드라이브 「멤버 관리」에서 그 계정 제거   ← 가장 잘 잊습니다
```

**③을 빠뜨리면 사이트에서는 막혔는데 시트로는 학생 개인정보를 계속 봅니다.**

- **본인 권한은 회수할 수 없습니다** — 다른 담당자가 합니다
- 「관리」 화면은 그 사람이 새로 열 때부터 막힙니다. 이미 열어 둔 화면에서는 첨부 파일이 **최대 1시간**
  더 열릴 수 있습니다(로그인 표시가 바뀌는 시간)
- 비상용 명령: `node scripts/grant-staff.mjs --env 이메일 --reason "사유" --revoke`

## 운영 시 지켜야 할 것

- **담당자는 최소 인원으로.** 담당자는 모든 신청자의 개인정보를 볼 수 있고, **다른 사람을 담당자로
  지정할 수도 있습니다**
- **인수인계 시 즉시 회수** — ①②(화면) + ③(시트·드라이브)
- 지정·회수 이력은 사이트가 기록합니다(D-120). 시트·드라이브 공유를 넣고 뺀 것만 따로 적어 두세요
  (감사 대응) — 날짜 · 이메일 · 누가 · 왜
