### 4′. 시설 예약 — 공개 전 확인 (D-56)

- [ ] 상단 메뉴 「시설 예약」이 보이고, 로그인 → 회원 등록 → 예약까지 이어지는지
- [ ] **담당자 → 예약 설정**에서 마감 요일·전달 요일·범위(4주)가 맞는지
- [ ] 시험 예약 한 건 → 담당자 「행정실 전달 명단」에 뜨는지 → [전달 완료] → 회원 화면에 확정으로 바뀌는지
- [ ] 🔴 **담당자 → 운영 설정을 한 번 저장** (저장 전엔 코드 가정값)
- [ ] 🔴 시험 예약을 지웁니다 — `reset-test-data.mjs` 가 예약 네 컬렉션(예약·자리 잠금·하루 열쇠·전달 기록)을 함께 지웁니다 (09-12). 운영 설정은 남습니다. 절차는 `04-테스트용-데이터-정리방법.md`
- [ ] 🔴 **가정값이 실제 정보로 바뀌었는지** — 마지막 시간 칸 · 취소 시한 ·
      마감·전달 요일 · 범위 · 문의 창구. `3-할일/02` J 표에 전부 ✅ 또는 ✏️ 가
      붙어 있어야 합니다. **하나라도 빈칸이면 열지 않습니다**
- [ ] 처리방침 이용 목적에 **「시설 예약 및 이용 관리」** 가 들어 있는지 (§4)
- [ ] 운영 방안 §4 의 회원 안내 문장을 공지 또는 예약 화면 안내에 넣었는지

## 2. 공고 등록 — 🔴 여기가 제일 중요합니다

[관리] → **프로그램 관리** → 새 프로그램

- [ ] **주소용 ID** — 나중에 못 바꿉니다. 예: `2026-ai-edu`
      · **`test-` 로 시작하지 않게** (정리 스크립트가 시험용으로 봅니다)
- [ ] 프로그램 이름 · 사업 연도(2026)
- [ ] **접수 시작 일시 / 마감 일시** — 분 단위까지. A-1 답변대로
- [ ] 🔴 **「신청 양식」에서 `AI-EDU 연구반 (2026)` 을 고릅니다**
      **이걸 안 고르면 기본 신청서로 접수됩니다.** 팀명·연구 계획을
      한 건도 못 받고, 나중에 알아도 **이미 낸 사람은 다시 받아야** 합니다
- [ ] 참여 방식 — **개인 신청**으로 둡니다
      (팀이어도 **구성원이 각자 신청**하는 방식입니다. '단체 프로그램'을

- [ ] 자유 기재란 · 첨부 — **A-1 답변에 따라.** 전용 양식이 이미 받고 있으니
      **비워 두는 것이 기본**입니다. 같은 걸 두 번 묻지 않게
- [ ] 소개(안내 내용) — 모집 대상·인원·지원 내용·일정
      · 🔴 **팀명을 팀원끼리 똑같이 적어야 한다**는 안내를 꼭 넣으세요.
        한 글자만 달라도 다른 팀이 됩니다 (화면에서도 경고하지만,
        공고문에 있어야 미리 정하고 옵니다)
      · **선정 결과는 공지사항에 명단으로 올린다**는 안내

## 7. 접수 중 — 하지 말아야 할 것

| 하지 말 것 | 왜 |
|---|---|
| 🚫 **「신청 양식」 바꾸기·끄기** | 이미 낸 사람과 이후 사람이 **다른 질문에 답한** 상태가 됩니다 |
| 🚫 접수 마감을 **앞으로 당기기** | 준비하던 사람이 못 냅니다. 꼭 필요하면 **공지 먼저** |
| 🚫 프로그램 이름 바꾸기 | 이미 낸 신청서에는 **옛 이름이 그대로** 남습니다 |
| 🚫 정리 스크립트 `--delete` (범위 지정 없이) | 실데이터가 들어온 뒤에는 **쓰면 안 됩니다** |

**괜찮은 것**: 오타 수정, 소개 문구 다듬기, 마감을 **뒤로** 미루기.
