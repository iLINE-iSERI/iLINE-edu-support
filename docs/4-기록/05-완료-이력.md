### 🧾 정산 영수증 → 드라이브 `02_정산` · 시트 「정산」 탭 (09-12 · D-65)

것 — 반려·재제출·승인·지급 완료가 있으니 정산 문서에 줄 번호를 기억해 두고
담당자가 상태를 바꿀 때마다 그 줄을 다시 씁니다. 파일은 숨은 속성으로
알아보아 재시도해도 두 번 올라가지 않고, 사람 폴더는 정산번호로 찾아
동명이인이 섞이지 않습니다. 담당자 카드에 반영 상태와 [지금 반영].
🔴 `DRIVE_SETTLEMENT_FOLDER_ID` 가 없으면 정산 건에 「설정 없음」 실패가 뜹니다 —
조용히 건너뛰지 않게 일부러 그렇게 했습니다.

첫 시험(09-12 iSERI)에서 둘째 장이 `Properties … limited to 124 bytes` 로
실패 — 파일 식별값에 Storage 경로를 통째로 넣었는데 한글 파일명이 들어가면
구글 제한(키+값 124바이트)을 넘습니다. **경로의 SHA-1 해시(40자)** 로 바꿔 해결.

같은 시험에서 나온 요청(iSERI): 반려 뒤 다시 낼 때 **기존 영수증이 뭔지 보이고
뺄 수 있어야** 한다. 폼 안에 기존 목록을 [삭제/되살리기]로 두고, 뺀 파일은
Storage 에서 지우며(규칙이 본인 삭제 허용), 동기화가 드라이브 사본을 휴지통으로
보냅니다 — 이 앱이 올린 표시가 있는 파일만 건드리고 사람이 직접 넣은 파일은
그대로 둡니다.

> 명세서(4-기록/07)에 "영수증은 안 나간다"로 적혀 있던 것을 고쳤습니다.
> D-38 결정은 원래 "영수증 → 드라이브 02_정산"이었는데 명세서가 더 엄격하게
> 적혀 있었습니다. 교수님 처리방침 위탁 항목에 영수증이 들어가야 합니다.

것까지 확인)

**원인 — `refresh()` 가 한 박자 뒤처진 계정 정보로 조회했다**

`AuthProvider` 의 `refresh` 가 리액트 상태 변수 `user` 를 읽고 있었습니다.
그런데 **그 값은 함수를 붙잡은 쪽 기준으로 낡아 있을 수 있습니다.**
가입 화면에서 정확히 그게 터졌습니다.

```
1) 가입 화면이 그려질 때는 아직 로그인 전
   → 이 화면이 쥔 refresh 안의 user 는 null
2) [가입 완료] → 계정 생성 → onAuthChange 가 돌지만
   회원 문서가 아직 없으므로 unregistered
3) 회원 문서 저장
4) refresh() → 1)의 낡은 null 로 조회 → guest 로 덮어씀   ← 여기
```

onAuthChange 는 이미 다 돌았으니 **다시 불릴 일이 없고**, 상태는 새로고침
전까지 `guest` 로 굳습니다. "가입은 됐는데 헤더는 로그아웃"이 정확히 이겁니다.

**고친 방법** — `refresh` 가 `getAuthClient().currentUser` 를 직접 묻습니다.
SDK 가 로그인 즉시 갱신하는 값이라 뒤처지지 않고, 의존성에서 `user` 가 빠져
**refresh 함수 자체가 안 바뀌므로** 낡은 참조를 쥘 수가 없습니다.

**함께 고친 것 — 조회 순서 뒤집힘 방지**
조회가 겹칠 때(로그인 직후 onAuthChange + refresh, 또는 로그아웃) **늦게 끝난
쪽이 이기는** 구조였습니다. 조회마다 번호를 붙여 최신이 아니면 결과를 버리게
했습니다. 로그아웃했는데 직전 조회가 뒤늦게 도착해 다시 '회원'이 되는 사고를
막습니다.

#### R-1′. 헤더가 '확인 중'을 '로그아웃'으로 그리던 문제

위와 **별개의 결함**이라 같이 고쳤습니다. 헤더 분기가
`로그인됨 → 가입미완료 → 확인불가 → 그 밖에 전부 [로그인/회원가입]` 이라
**`loading` 이 마지막 칸으로 떨어졌습니다.** 확인 중인데 화면이 **"당신은
로그아웃 상태"라고 단언**하는 셈입니다. 이제 `확인 중…` 을 표시합니다.

> ⚠️ **09-05 에 `MemberGate` 에서 고쳤던 것과 똑같은 실수입니다.**
> 그때 `loading` 상태를 새로 만들었는데 **헤더는 그 구분을 쓰지 않고
> 있었습니다.** → **상태를 늘리면 그 상태를 읽는 곳을 전부 찾아 고칠 것.**

#### R-3. 로그인 화면이 **이미 로그인한 사람에게도 폼을 보여주던 문제**

09-07 휴대폰 시험에서 드러났습니다. 그 시험은 **아직 push하지 않은 배포본**,
즉 R-1이 살아 있는 옛 코드에서 한 것이라 증상은 R-1 그대로였는데
(가입 직후 `guest` → 마이페이지가 로그인 화면으로 되돌림),
**"새로고침해도 그대로"** 는 R-1 만으로 설명되지 않았습니다.

원인은 별개였습니다 — **`/login` 이 인증 상태를 아예 보지 않았습니다.**
새로고침하면 헤더는 로그인 상태로 바뀌는데, 이 화면은 아무것도 모른 채
**폼만 계속 보여줍니다.** 본인은 로그아웃된 줄 압니다.
회원가입 화면에는 같은 처리가 있었는데 **여기만 빠져 있었습니다.**

R-1을 고쳐도 **북마크·뒤로가기로 이 주소에 다시 오면 같은 혼란**이 남으므로
따로 고쳤습니다. 이미 회원이면 원래 가려던 곳으로, 가입 미완료면 등록
화면으로 보냅니다. `error`(확인 불가)일 때는 **보내지 않습니다** — 어디로
보낼지 모르기 때문이고, 그 안내는 헤더와 등록 화면이 맡습니다.

> 📌 **여기서 배운 것** — 휴대폰과 PC의 차이가 아니라 **옛 코드와 새 코드의
> 차이**였습니다. 시험 결과가 이상하면 **그 화면이 어느 버전을 돌고 있는지**
> 부터 확인해야 합니다. 다만 그 시험이 아니었으면 R-3은 못 찾았을 것입니다.

#### R-2. 모바일 메뉴에 `error` 분기가 없던 문제

데스크톱에는 회원 조회 실패 시 안내 + 로그아웃이 있는데 **모바일 햄버거에는
그 칸이 없어** `로그인 / 회원가입` 이 떴습니다. **이미 회원인 사람이 다시
가입하려 들게** 만드는 화면입니다. D-24(모든 화면이 스마트폰에서 완전 동작)
위반이라 함께 고쳤습니다. `unregistered` 일 때 모바일에 로그아웃 버튼이 없던
것도 함께 채웠습니다 — 다른 계정으로 바꿀 방법이 없었습니다.

> 새로 받아야 합니다. 다음에 주소를 또 바꾸게 되면 이 점만 기억하면 됩니다.

**09-08 외부 DNS 조회 결과 (1.1.1.1 · 8.8.8.8 기준)**

```
aiedu.iline.or.kr        CNAME  68d8ea697b9a7086.vercel-dns-017.com.   ✅
aiedu.iline.or.kr        A      216.198.79.65 / 64.29.17.65            ✅ Vercel IP
                                → Cloudflare 대역이 아니므로 Proxy 꺼짐이 확인됨
edusupport.iline.or.kr   —      NXDOMAIN                               ✅ 깨끗이 제거
_vercel.iline.or.kr      TXT    aiedu... + iline.or.kr...              ✅ 2줄 공존
iline.or.kr              A      76.76.21.21                            ✅ iLINE 무사
www.iline.or.kr          CNAME  cname.vercel-dns.com.                  ✅ iLINE 무사
_vercel.www.iline.or.kr  TXT    www.iline.or.kr,4b46...                ✅ iLINE 무사
```

> **Proxy 상태를 IP로 판별하는 법** — Cloudflare 프록시가 켜져 있으면
> A 레코드가 Cloudflare 대역(`104.21.x` · `172.67.x`)으로 나옵니다.
> Vercel IP가 그대로 보이면 **DNS only** 입니다. 화면을 못 볼 때 쓸 수 있는
> 확인법입니다.

### 📌 iLINE 과 주소록을 함께 쓴다 — 건드리면 안 되는 줄

| Type | Name | 값 | 주인 |
|---|---|---|---|
| A | `@` | `76.76.21.21` | **iLINE — 손대지 말 것** |
| CNAME | `www` | `cname.vercel-dns.com` | **iLINE — 손대지 말 것** |
| TXT | `_vercel` | `...=iline.or.kr,129d3...` | **iLINE — 손대지 말 것** |
| TXT | `_vercel.www` | `...=www.iline.or.kr,4b46...` | **iLINE — 손대지 말 것** |
| CNAME | `aiedu` | `68d8ea697b9a7086.vercel-dns-017.com` | 지원사업 |
| TXT | `_vercel` | `...=aiedu.iline.or.kr,c5cb47...` | 지원사업 |

*(옛 `edusupport` CNAME·TXT 2줄은 09-08 삭제 완료 — NXDOMAIN 확인)*

**iLINE 줄을 고치거나 지우면 운영 중인 iLINE 이 멈춥니다.**
`_vercel` TXT 는 **한 이름에 여러 줄이 공존**합니다 — 지울 때 값을 보고
지원사업 것만 고르세요. CNAME 은 **반드시 Proxy 회색(DNS only)** —
오렌지면 인증서 발급이 실패합니다.
