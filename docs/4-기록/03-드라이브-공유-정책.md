# 공유 드라이브 외부 공유 정책 — 협의용 정리

> 교수님·전산 담당자와 의논할 때 그대로 보여드릴 수 있게 정리한 문서입니다.
> 작성일: 2026-09-05 (실제로 시험해 본 결과 기준)

---

## 1. 한 줄 요약

지원사업 사이트가 신청서를 구글 공유 드라이브에 자동으로 올리는데, 그 일을 하는
**서버 계정이 조직 입장에서 "외부 사용자"로 분류**됩니다. 그래서 공유 드라이브의
외부 사용자 접근을 막으면 **자동 저장이 멈춥니다.**

지금은 그 항목만 켜 두고 나머지를 조여서 쓰고 있습니다. 더 엄격하게 가려면
**그 계정 하나만 예외로 허용**하는 설정이 필요하고, 그건 관리 콘솔 권한이 있어야 합니다.

---

## 2. 무슨 일이 일어나는가

```
학생이 사이트에서 신청서 제출
        ↓
사이트 서버가 신청서 PDF를 만들어
        ↓
공유 드라이브 `01_신청` 폴더에 저장
        ↓
담당자는 스프레드시트에서 링크를 눌러 확인
```

이 "사이트 서버"가 구글에 접속할 때 쓰는 것이 **서비스 계정**입니다.

```
firebase-adminsdk-xxxxx@iline-edu-support.iam.gserviceaccount.com
```

사람이 아니라 **프로그램용 계정**입니다. 로그인 화면도 비밀번호도 없고,
우리 서버 코드만 이 계정으로 행동할 수 있습니다.

**문제는 도메인입니다.** 끝이 `.iam.gserviceaccount.com` 이라 연구소 도메인과
다르기 때문에, 구글은 이 계정을 **조직 외부 사용자**로 분류합니다.

---

## 3. 실제로 시험해 본 결과 (09-05)

공유 드라이브 설정에서 **"연구소 외부 사용자가 파일에 액세스하도록 허용"** 을 끄고
신청서를 제출해 봤습니다.

```
구글 시트 반영 실패 — [드라이브 업로드] File not found: 1TBhFtDrbc...
```

폴더가 없어진 게 아니라 **서버 계정 눈에 안 보이게 된 것**입니다. 다시 켜니
정상 동작했습니다.

## 4. 현재 설정 — 이대로도 안전한가

| 항목 | 현재 | 판단 |
|---|---|---|
| 연구소 **외부 사용자** 액세스 | **켬** | 끄면 자동 저장이 멈춤 |
| **공유 드라이브 멤버가 아닌** 사용자 액세스 | **끔** ✅ | **이것이 실질적인 방어선** |
| 콘텐츠 관리자의 **폴더 공유** | **끔** ✅ | 공유 권한을 관리자에게만 |
| 참여자·콘텐츠 관리자 **다운로드** | 켬 | 끄면 담당자가 신청서를 못 받음 |
| 댓글 작성자·뷰어 **다운로드** | **끔** ✅ | |

**두 번째 항목이 핵심입니다.** 이걸 꺼 두었기 때문에, 링크가 밖으로 새어 나가도
**멤버가 아니면 아무것도 못 봅니다.** 첫 번째 항목은 "누구를 멤버로 초대할 수
있는가"를 제한하는 것이라, **멤버 목록만 관리하면 통제됩니다.**

현재 멤버는 담당자 계정들과 위 서비스 계정뿐입니다.

**즉, 지금 상태에서 학생 개인정보가 조직 밖으로 나갈 경로는 없습니다.**

## 5. 더 엄격하게 가려면 — 요청할 내용

Google Workspace **관리 콘솔** 권한이 있는 분께 요청해야 합니다.

> **요청 사항**
> 공유 드라이브 `교원양성지원사업` 에 대해 외부 공유를 차단하되,
> 아래 서비스 계정 하나만 **예외로 허용**해 주세요.
>
> ```
> firebase-adminsdk-xxxxx@iline-edu-support.iam.gserviceaccount.com
> ```
>
> 관리 콘솔 경로: **앱 → Google Workspace → Drive 및 문서 → 공유 설정**
> — 외부 공유 대상을 **허용 목록(allowlist)** 방식으로 두고 위 도메인/계정을 등록

허용되면 공유 드라이브 설정의 첫 번째 항목도 끌 수 있고, **자동 저장은 계속 동작**합니다.

## 6. 의논할 때 나올 만한 질문

**"외부 계정에 우리 자료 접근을 허용하는 것 아닌가?"**
서비스 계정은 제3자가 아니라 **우리 사이트의 서버 그 자체**입니다. 이름과 도메인이
외부처럼 보일 뿐, 이 계정으로 행동할 수 있는 것은 우리 코드뿐입니다.
비유하자면 사무실 복합기에 계정을 하나 준 것과 같습니다.

**"그 계정이 유출되면?"**
계정에 접근하려면 **비공개 키 파일**이 필요합니다. 그 키는 Vercel 서버의
환경변수에만 있고 브라우저로 내려가지 않으며, 코드 저장소에도 없습니다.
유출이 의심되면 **Firebase 콘솔에서 키를 즉시 폐기**하고 새로 발급하면 됩니다.
그 순간부터 옛 키는 아무것도 못 합니다.

**"굳이 지금 해야 하나?"**
급하지 않습니다. §4처럼 두 번째 항목을 꺼 둔 것으로 실질적 차단은 되어 있습니다.
**감사 대비로 "외부 공유 전면 차단"이 문서상 필요할 때** 진행하면 됩니다.

**"안 하면 무엇이 남는가?"**
"연구소 외부 사용자를 멤버로 초대할 수 있는 상태"가 유지됩니다. 담당자가
실수로 외부인을 멤버로 넣으면 막히지 않습니다. 그래서 **멤버 목록을 주기적으로
점검**하는 것이 대체 통제 수단입니다.
