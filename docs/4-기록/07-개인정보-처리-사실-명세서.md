| | |

### 1-3. 동의 기록

| | |
|---|---|
| **왜** | 동의를 받았다는 증명 |
| **무엇** | 동의 목적 · **동의 여부(O/X)** · **약관 문구 버전** · **동의 일시** |

### 1-4. 프로그램 신청

| | |
|---|---|
| **왜** | 접수 · 심사 · 선정 |
| **무엇** | ① 회원 정보의 **제출 시점 사본**(이름·유형·소속·학과·학번·학년·직위·연락처·이메일) ② **초상권 활용 동의 여부**와 문구 버전 ③ 프로그램 전용 항목의 답 ④ 자유 기재란 ⑤ 첨부 파일 ⑥ 취소 시 사유(선택) |
| **어디** | Firestore `support_applications` · 첨부와 신청서 PDF 는 Firebase Storage · **구글 시트** · **구글 공유 드라이브** |
| **누가 보나** | 본인 · 담당자 |
| **언제까지** | ⚠️ 가입 동의서 기준 **"사업 종료 후 3년"** — §5 ④ 참고 |

**왜 사본을 뜨는가** — 회원이 나중에 연락처를 바꿔도, 그 신청서는 **제출 당시의
원본**이어야 하기 때문입니다. 그래서 회원 정보와 신청서 정보는 **따로 보관**됩니다.

**초상권 동의는 신청할 때마다 다시 받습니다.** 같은 사람이 A 프로그램은
동의하고 B 프로그램은 거부할 수 있습니다. 사진을 쓸 때는 *"이 사람이 동의했나"*
가 아니라 *"그 사진이 나온 프로그램의 신청건이 동의했나"* 를 봐야 합니다.

*확인: `lib/types/index.ts` (Application, ApplicantSnapshot), `lib/firebase/applications.ts`*

## 3. **받지 않는 것** — 이것도 중요합니다

방침에 "받는다"고 적히면 **안 받는데 받는다고 한 것**이 되어 그 또한 어긋납니다.

| 안 받음 | 근거 |
|---|---|
| **주민등록번호** | 어디에서도 묻지 않습니다 |
| **신분증 사본** | D-40 — 교수님 확인 후 폐기 |
| **통장 사본** | D-40 — 회계 확인 후 폐기. **계좌번호만** 받습니다 |
| **재직·재학 증명서** | 받지 않습니다 |
| **동반자·팀원 명단** | 남의 개인정보를 대신 입력하는 것이라 받지 않습니다 |
| **주소** | 묻지 않습니다 |
| **생년월일·성별** | 묻지 않습니다 |

> 📌 단체 프로그램에서 대표자가 팀원 명단을 내는 방식은 **코드에 자리는 있으나
> 실제로 쓰지 않습니다.** 팀으로 활동해도 **구성원이 각자 신청**합니다.
> 그래서 지금은 **대리 수집이 일어나지 않습니다.**

## 4. 열람·삭제

| | 지금 어떻게 되어 있나 |
|---|---|
| **본인 열람** | 마이페이지에서 자기 신청·정산을 봅니다 |
| **본인 수정** | ✅ **마이페이지 → 내 정보 → [수정하기]** (09-09 추가). 이름·유형·소속·학과·학번·학년·직위·연락처를 본인이 고칩니다. **이메일과 동의 이력은 못 고칩니다** |
| **본인 삭제** | 사이트에서 **불가능합니다.** 보안 규칙에서 삭제를 막아 두었습니다(보존 목적) |
| **탈퇴** | 삭제가 아니라 **상태 변경**(`withdrawn`)으로 처리하도록 설계했습니다 |
| **관리자 삭제** | 콘솔에서 사람이 직접. 흔적이 **다섯 곳**에 나뉘어 있어 순서대로 지워야 합니다 |

🔴 **여기에 결정이 필요합니다.** 개인정보 보호법은 정보주체의 **열람·정정·삭제
요구권**을 보장합니다.

- **열람** ✅ 마이페이지
- **정정** ✅ 회원정보 수정 (09-09 추가)
- **삭제** ❌ **창구가 없습니다** — 사이트에서 지울 수 없게 막아 두었고(보존
  목적), 탈퇴도 화면이 없습니다

삭제·탈퇴 요구를 **누구에게 어떻게 하는지**를 정해 방침에 적어야 합니다.
"담당자에게 연락하면 처리한다"라도 좋지만, **그 연락처가 있어야** 합니다.
