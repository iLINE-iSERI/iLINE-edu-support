# 디자인 규칙 — 한 서비스처럼 보이게 하는 기준

> 작성: 2026-09-15 (D-71 M-0) · iSERI 검토 대기
> **왜 이 문서인가** — 09-14 미팅에서 "전반적인 디자인을 특징 있게"가 나왔다. 특징은
> 색·소재로 만들지만, 그 전에 **버튼·글꼴·간격이 화면마다 다르면** 어떤 색을 입혀도
> 한 서비스로 보이지 않는다. 이 문서는 색과 무관하게 먼저 통일할 것을 정하고,
> 색은 브레인스토밍 뒤 §2 표만 바꾸도록 자리를 비워 둔다.
>
> 코드의 단일 출처는 `app/globals.css`(CSS 변수)와 `tailwind.config.ts` 다. 이 문서는
> **그 값들이 왜 그런지**와 **아직 코드에 없는 규칙**을 적는다. 둘이 어긋나면 코드를 고친다.

---

## 0. 원칙 셋

1. **이용자는 네 순간에 온다** — 공고 확인 · 신청 · 결과 확인 · 정산. 그 순간에 필요한
   것이 첫눈에 보이면 좋은 디자인이고, 그것을 가리면 나쁜 디자인이다. 장식은 그 다음.
2. **국비 사업 사이트다.** 신뢰는 화려함이 아니라 일관성에서 온다 — 같은 버튼, 같은 글꼴,
   같은 간격이 반복될 때 "관리되는 사이트"로 읽힌다. 특징은 색과 소재 한두 군데면 충분.
3. **본문은 무채색, 색은 행동과 상태에만.** 파란 것은 누르는 것, 주황은 고쳐야 하는 것,
   초록은 끝난 것. 이 셋 말고 색을 늘리지 않는다.

## 2. 색 — 🔶 브레인스토밍 뒤 교체 (지금은 현행 값)

> 09-14 교수님: "iLINE과 꼭 통일할 필요 없다." → 남색을 유지할지, 사범대학·연구소 색 중
> 무엇을 쓸지 **아직 정하지 않았다.** 아래는 현행 값이고, 결정되면 이 표와
> `globals.css` `:root` 블록만 바꾼다. 규칙(어디에 무슨 역할의 색을 쓰는가)은 바뀌지 않는다.
>
> **톤은 정했다 (09-15 iSERI, D-72).** 교수님 "칙칙하다"에 대한 답으로 시안 3안 중
> **홈 = 진한 밴드(톤 1: 주색 바탕 + 흰 카드 + 그림자)**, **안쪽 화면 = 흰 바탕 + 굵은 선
> (톤 2: 검은 글자, 카드 왼쪽 주색 바, 절 제목 옆 세로 바)**. 라이트 블루(톤 3)는 뚜렷함이
> 약해 뺐다. 설명 글자 `--text-muted` 를 gray-600 → **gray-700** 으로 진하게 했다.

| 역할 | 토큰 | 현행 | 어디에 |
|---|---|---|---|
| 주색 (행동) | `--brand` / `brand-600` | #1e3a8a 남색 | Primary 버튼 바탕 · 링크 · 선택된 탭 |
| 주색 진하게 | `--brand-strong` / `brand-700` | #172e6e | hover |
| 주색 옅게 | `--brand-soft` / `brand-50` | #e8edfa / #eef2fb | 강조 상자 바탕 · 배지 |
| 바탕 | `--bg` · `--bg-subtle` · `--bg-elevated` | #fff · #f5f7fb · #fff | 페이지 · 구획 띠 · 카드 |
| 선 | `--border` · `--border-strong` | gray-200 · gray-300 | 카드 테두리 · 입력 테두리 |
| 글자 | `--text` · `--text-muted` · `--text-subtle` | gray-900 · 600 · 500 | 본문 · 설명 · 힌트 |
| 상태 | `--status-*` | 제출 #2563eb · 보완 #d97706 · 선정 #15803d · 나머지 회색 | 배지 · 안내 상자 · Danger 버튼 |

**바꿀 때 지킬 것** — 흰 글자를 올리는 색은 **대비 4.5:1 이상**(KWCAG). 밝은 원색(청록·
초록·주황)은 바탕·바·배지에만 쓰고 글자·버튼에는 진한 파생색을 쓴다(인트로에서 배운 것).
다크모드 값은 `globals.css` 아래 블록에 같이 있다 — 라이트만 바꾸고 다크를 잊지 않는다.

## 3. 글자 크기 — 다섯 단계

| 단계 | 휴대폰 / PC | Tailwind | 굵기 | 쓰는 곳 |
|---|---|---|---|---|
| 페이지 제목 | 20 / 24px | `text-xl sm:text-2xl` | 800 | `PageHeader` h1 (현행) |
| 절 제목 | 18 / 20px | `text-lg sm:text-xl` | 700 | 화면 안 큰 구획 h2. **지금은 `text-lg` 고정** → PC에서 한 단계 키운다 |
| 카드 제목 | 16px | `text-base` | 700 | 카드·목록 항목 |
| 본문 | 15~16px | `text-[15px]`/`text-base` | 400 | 문단. `leading-relaxed` |
| 보조 | 13~14px | `text-sm` / `text-xs` | 400~600 | 라벨 · 힌트 · 배지 · 표 안 |

홈 첫 화면 카드 제목만 예외 — 1개일 때 `text-2xl sm:text-3xl`, 2·3개 `text-[22px]`
(사업명 히어로는 09-15에 뺐다). 제목 아래 설명은 항상 `text-ink-muted`. **절 제목 위 여백은 56px(`space-y-14`)** — "주제가 바뀐다"가 여백으로 보이게.

## 4. 버튼 — 네 종류만

> 지금은 25개 파일에 인라인 클래스로 10~15가지 변형이 있다(모서리 lg/xl, 굵기, 여백이
> 조금씩 다름). `components/ui/Button.tsx` 하나로 모으고 아래 넷만 허용한다.
> **동작은 바꾸지 않는다** — 클래스만 교체.

| 종류 | 생김새 | 언제 |
|---|---|---|
| **Primary** | 주색 바탕 · 흰 글자 700 · `rounded-xl` · 높이 44 · `px-6` · hover 진하게 · disabled 50% | 화면에서 **가장 중요한 다음 단계** 하나 (제출·신청·저장). 한 화면에 하나가 원칙 |
| **Secondary** | 테두리 `border-line-strong` · 글자 본문색 700 · 나머지 Primary와 같음 · hover `bg-subtle` | 보조 행동 (목록 보기 · 돌아가기 · 파일 열기) |
| **Danger** | 주황(`status-revision`) 테두리·글자 · 바탕 없음 · hover 주황 10% | 되돌리기 어려운 것 (신청 취소 · 삭제 · 반려) |
| **Text** | 밑줄 · 600 · `text-sm` · 바탕·테두리 없음 | 문장 안 행동 (수정하기 · 자세히) |

공통: 최소 높이 44px(`touch-target`), 글자 15px, 아이콘 없이 글자만(아이콘 라이브러리를
쓰지 않는다 — 화살표는 `→` 문자). 휴대폰(≤639px)에서 폼의 Primary 는 **가로 100%**.

## 5. 입력 — `Field`·`Select` 로 통일

> 지금 `Field`는 로그인·가입·회원정보에서만 쓰고, 신청서·정산·예약·담당자 폼은 각자
> `<input>`에 클래스를 직접 쓴다. 전부 `Field`로 바꾼다 — 검증 로직은 그대로.

| 항목 | 값 |
|---|---|
| 라벨 | 위, `text-sm font-semibold`, 필수는 주황 `*` + sr-only "필수" |
| 힌트 | 라벨 아래 `text-xs text-ink-subtle` |
| 칸 | `rounded-xl border border-line-strong bg-surface p-3`, 글자 16px(iOS 확대 방지 — `globals.css` base) |
| 포커스 | `outline 3px var(--brand)` (전역) |
| 오류 | 칸 아래 `text-sm text-status-revision`, 칸 테두리 주황. **맨 위 한 줄 안내가 아니라 칸 옆** (담당자 화면은 09-06에 이미 이렇게) |
| 라디오 2지선다 | `ConsentBlock` 방식(동의함/동의하지 않음 카드형) 유지 |

## 6. 카드·상자

| 종류 | 클래스 | 쓰는 곳 |
|---|---|---|
| 기본 카드 | `rounded-2xl border border-line bg-surface p-5 sm:p-6` | 신청 건 · 정산 · 예약 · 담당자 목록 (현행 27곳) |
| 작은 카드 | `rounded-xl border border-line bg-surface p-5` | 홈 바로가기 · 인재상 · 선택지 3~4개 나열 |
| 안쪽 상자 | `rounded-xl bg-subtle p-4` | 카드 안의 보조 정보 |
| 강조 상자 | `rounded-2xl border border-brand-200 bg-brand-soft p-6` | 비전 · 접수 중 공고 · "지금 할 일" |
| 안내(상태) | `rounded-lg bg-status-*/10 px-3 py-2 text-sm text-status-*` | 보완 요청 · 오류 · 완료 알림 |

**모서리 규칙** — 카드 `2xl`(16px) · 버튼·입력·작은 카드 `xl`(12px) · 안내·배지 `lg`(8px)
또는 `full`. 지금은 셋이 섞여 있다 → 위 표대로 정리.
**그림자** — 기본 없음. hover 로 떠오르는 링크 카드만 `shadow-sm`. 공공 사이트 톤.

## 7. 간격·폭·반응형

| 항목 | 값 | 비고 |
|---|---|---|
| 페이지 폭 | **1140px** (`max-w-container`) · 좌우 16/24/32px → **1440 이상 1320px · 1920 이상 1480px** (09-18 · D-79) | 담당자 표가 있어 인트로(1040)보다 넓게. 큰 모니터에서 좌우가 40% 넘게 비어 단계를 둠. 그 위로는 더 안 넓힘 — 한 줄이 길어지면 읽기 어려움 |
| 화면 위아래 | `py-10 sm:py-14` | `PageHeader` 아래 본문 |
| 절 사이 | 56px (`space-y-14`) | |
| 카드 안 | 20 / 24px | |
| 요소 사이 | 12px (`gap-3`, `mt-3`) · 촘촘한 것 8px | |
| 반응형 기준 | **640 / 820 / 1024** (`sm/md/lg`) + **1440 / 1920** (`xl/2xl`, 09-18) | 기본이 휴대폰, 위로 확장 (D-24). xl·2xl 은 폭 단계용 |
| 글자 크기 흐름 | `html` font-size **16px → 18px** (1440~2560px 사이에서 선형, `globals.css`) | Tailwind 글자·간격이 전부 rem 이라 이 한 줄로 화면 전체가 비례해 커진다. `text-[15px]` 처럼 px 로 못 박은 곳은 안 커짐 — 새로 쓸 때 rem 계열(`text-sm` 등)을 쓸 것 |
| 격자 | 카드 3~4개 나열: 휴대폰 1열 → `sm` 2열 → `lg` 3~4열 | |
| 표 | `table-scroll`로 감싸 가로 스크롤 — 본문이 밀리지 않게 | |

## 8. 공용 컴포넌트 — 있는 것과 만들 것

| 컴포넌트 | 상태 | 할 일 |
|---|---|---|
| `PageHeader` | 있음 | 유지. 부제는 화면을 설명하는 말이 아니라 **이용자가 여기서 하는 일** 한 줄 |
| `Field` · `Select` | 있음 | 신청서·정산·예약·담당자 폼으로 확대 |
| `Badge` | 있음 | 유지 |
| `ConsentBlock` | 있음 | 유지 |
| `SubNav` | 있음 | 유지 |
| `EmptyState` · `Placeholder` | 있음 | 문구가 "다음에 뭘 하라"를 말하는지 점검 |
| **`Button`** | ✅ 09-15 | §4 네 종류. `href` 주면 링크. 홈에서 첫 사용 — 나머지 화면은 차례로 교체 |
| **`SectionTitle`** | ✅ 09-15 | 절 제목 + 설명 + 오른쪽 링크. 왼쪽 세로 바. `invert` 로 진한 바탕 위에도 |
| `Card` | 없음 | 선택 — 클래스 문자열 반복이 많으면 그때 |

## 9. 적용 순서 (M-5 와 연결)

1. 글꼴 ✅ → 2. `Button`·`SectionTitle` 신설 ✅ → 3. 홈 재구성(M-1) ✅ 09-15 — 기준 화면
→ 4. 마이페이지 → 신청서 → 정산 → 예약 → 담당자 순으로 교체 →
5. 색 결정(브레인스토밍) → §2 표와 `globals.css` 교체 → 6. 전 화면 PC·휴대폰 캡처.

**하지 않는 것** — 라우트·링크·폼 검증·규칙·데이터 구조. 디자인 작업으로 동작이
바뀌면 그건 버그다.
