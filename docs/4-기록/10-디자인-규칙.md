# 디자인 규칙 — 한 서비스처럼 보이게 하는 기준

> 작성: 2026-09-15 (D-71 M-0) · **09-18 §2 색·톤 확정 (D-81)**
> **왜 이 문서인가** — 09-14 미팅에서 "전반적인 디자인을 특징 있게"가 나왔다. 특징은
> 색·소재로 만들지만, 그 전에 **버튼·글꼴·간격이 화면마다 다르면** 어떤 색을 입혀도
> 한 서비스로 보이지 않는다. 이 문서는 색과 무관하게 먼저 통일할 것을 정하고,
> 색은 브레인스토밍 뒤 §2 표만 바꾸도록 자리를 비워 둔다.
>
> 코드의 단일 출처는 `app/globals.css`(CSS 변수)와 `tailwind.config.ts` 다. 이 문서는
> **그 값들이 왜 그런지**와 **아직 코드에 없는 규칙**을 적는다. 둘이 어긋나면 코드를 고친다.

---

## 0. 원칙 셋

1. **이용자는 네 순간에 온다** — 공고 확인 · 신청 · 결과 확인 · 정산. 그 순간에 필요한
   것이 첫눈에 보이면 좋은 디자인이고, 그것을 가리면 나쁜 디자인이다. 장식은 그 다음.
2. **국비 사업 사이트다.** 신뢰는 화려함이 아니라 일관성에서 온다 — 같은 버튼, 같은 글꼴,
   같은 간격이 반복될 때 "관리되는 사이트"로 읽힌다. 특징은 색과 소재 한두 군데면 충분.
3. **본문은 무채색, 색은 행동과 상태에만.** 파란 것은 누르는 것, 청록은 열린 것·좋은 것,
   귤색은 내가 할 일이 있는 것, 슬레이트는 기다리는 것. 이 넷 말고 색을 늘리지 않는다 (§2).

### 토큰은 「R G B」 세 숫자다 (09-18)

`globals.css` 의 값은 `37 99 235` 처럼 숫자 셋이고 `tailwind.config.ts` 가
`rgb(var(--x) / <alpha-value>)` 로 감싼다. 그래서 **`bg-status-approved/12` 같은 투명도
수식이 이제 통한다.** 09-18 이전에는 #hex 여서 투명도 붙은 클래스 30여 곳(배지 바탕,
보완·선정 안내 상자의 바탕·테두리)이 CSS 로 **안 나가고 있었다** — 배지가 글자만 찍히고
안내 상자가 테두리 없이 뜨던 원인. CSS 안에서 직접 쓸 때는 `rgb(var(--brand))`.
(작업지시서 규칙 ⑪ "변수 색에 투명도 금지"는 이것으로 뒤집혔다.)

### 그림자·모서리·호버

- 카드 `shadow-card` = `0 1px 3px rgba(15,23,42,.04), 0 4px 12px rgba(15,23,42,.03)`.
  **`.card`** = `rounded-2xl border border-line bg-surface shadow-card`.
- **`.card-link`** = 카드 + 올리면 3px 떠오르며 `shadow-card-hover`. **누르면 어디로 가는
  카드에만** (홈 바로가기 · 프로그램 목록 카드). 입력 폼 카드에는 절대 안 건다 — 타이핑
  중에 들썩인다.
- 버튼·배지 `rounded-lg`(8px) · 카드 `rounded-2xl`(16px).
- 헤더: `bg-surface/85 backdrop-blur-md` — 85% 흰 바탕 + 뒤를 흐림. 09-17 "투명해서 겹친다"
  는 블러 없는 95%(실제로는 토큰 문제로 완전 투명) 이야기였다. 겹쳐 보이면 `bg-surface` 로.
- 제목(h1~h3) 자간 -0.015em · 행간 1.3 (전역 base). 본문은 -0.01em 그대로 — 한글 본문에
  음수 자간을 더 주면 답답하다.

### 다크 모드

`globals.css` 아래 블록에 같은 토큰의 다크 값이 있다(`prefers-color-scheme: dark`).
**OS 가 다크면 자동으로 켜진다** — 사이트에 스위치는 없다. 라이트만 바꾸고 다크를 잊지
않는다. 지시서의 하드코딩 색(`bg-white/85` `text-slate-900` …)을 그대로 넣지 않고 토큰으로
번역한 이유가 이것이다.

### 되돌리기

남색으로: `--brand 30 58 138` · `--brand-strong 23 46 110` · `--brand-soft 232 237 250` 과
`tailwind.config.ts` 의 brand 팔레트(옛 값은 git 이력 D-80). 귤색을 빼려면 `--warn*` 을
`--wait*` 값으로. 캔버스를 흰색으로: `--bg 255 255 255`, `--bg-subtle 245 247 251`.

## 4. 버튼 — 네 종류만

> 지금은 25개 파일에 인라인 클래스로 10~15가지 변형이 있다(모서리 lg/xl, 굵기, 여백이
> 조금씩 다름). `components/ui/Button.tsx` 하나로 모으고 아래 넷만 허용한다.
> **동작은 바꾸지 않는다** — 클래스만 교체.

| 종류 | 생김새 | 언제 |
|---|---|---|
| **Primary** | 주색 바탕 · 흰 글자 700 · `rounded-lg`(09-18) · 높이 44 · `px-6` · hover 진하게 · disabled 50% | 화면에서 **가장 중요한 다음 단계** 하나 (제출·신청·저장). 한 화면에 하나가 원칙 |
| **Secondary** | 테두리 `border-line-strong` · 글자 본문색 700 · 나머지 Primary와 같음 · hover 테두리·글자 주색, 바탕 `brand-soft` | 보조 행동 (목록 보기 · 돌아가기 · 파일 열기) |
| **Danger** | 귤색(`warn-ink`) 테두리·글자 · 바탕 없음 · hover `warn-soft` | 되돌리기 어려운 것 (신청 취소 · 삭제 · 반려) |
| **Text** | 밑줄 · 600 · `text-sm` · 바탕·테두리 없음 | 문장 안 행동 (수정하기 · 자세히) |

공통: 최소 높이 44px(`touch-target`), 글자 15px, 아이콘 없이 글자만(아이콘 라이브러리를
쓰지 않는다 — 화살표는 `→` 문자). 휴대폰(≤639px)에서 폼의 Primary 는 **가로 100%**.

## 5. 입력 — `Field`·`Select` 로 통일

> 지금 `Field`는 로그인·가입·회원정보에서만 쓰고, 신청서·정산·예약·담당자 폼은 각자

| 항목 | 값 |
|---|---|
| 라벨 | 위, `text-sm font-semibold`, 필수는 주황 `*` + sr-only "필수" |
| 힌트 | 라벨 아래 `text-xs text-ink-subtle` |
| 칸 | `rounded-xl border border-line-strong bg-surface p-3`, 글자 16px(iOS 확대 방지 — `globals.css` base) |
| 포커스 | `outline 3px var(--brand)` (전역) |
| 오류 | 칸 아래 `text-sm text-status-revision`, 칸 테두리 주황. **맨 위 한 줄 안내가 아니라 칸 옆** (담당자 화면은 09-06에 이미 이렇게) |
| 라디오 2지선다 | `ConsentBlock` 방식(동의함/동의하지 않음 카드형) 유지 |

| 종류 | 클래스 | 쓰는 곳 |

| 기본 카드 | **`.card`** = `rounded-2xl border border-line bg-surface shadow-card` + `p-5 sm:p-6` | 신청 건 · 정산 · 예약 · 담당자 목록. 09-18 부터 그림자 |
| 링크 카드 | **`.card-link`** (카드 + 호버 떠오름) | 홈 바로가기 · 프로그램 목록 카드 — 누르면 어디로 가는 것만 |

**그림자** — 카드는 `shadow-card`(얕음), 링크 카드 hover `shadow-card-hover`. 09-18 이전엔 "기본 없음"이었다.

| `SubNav` | 있음 | 유지 |

| **`Button`** | ✅ 09-15 | §4 네 종류. `href` 주면 링크. 홈에서 첫 사용 — 나머지 화면은 차례로 교체 |
