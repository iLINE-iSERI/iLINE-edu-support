## 1. 데이터베이스

### 데이터베이스는 **하나뿐**입니다

로컬(`npm run dev`)에서 시험해도 **진짜 데이터베이스에 저장됩니다.**
로컬은 "화면만 내 컴퓨터"지 별도 연습장이 아닙니다.

→ 시험용 공고는 id 를 **`test-` 로 시작**하게 만드세요. 나중에 골라내기 쉽습니다.

### 보안 규칙은 push 로 올라가지 않습니다 — `npm run rules` 로 올립니다

`firestore.rules` · `storage.rules` 를 고쳐서 push 해도 **아무 일도 일어나지
않습니다.** 사이트(Vercel)와 규칙(Firebase)은 서로 다른 곳에 올라갑니다.

**09-12부터는 콘솔에 붙여넣지 않습니다.** 저장소 폴더에서

```
npm run rules
```

한 줄이면 저장소의 두 규칙 파일이 **그대로** 올라갑니다. 문법이 틀리면 올리기
전에 멈춰서 알려 줍니다. `npm run rules:check` 는 올리지 않고 검사만 합니다.

**처음 한 번만** (PC 마다 · 사람마다):
```
npm i -g firebase-tools      ← 도구 설치
firebase login               ← 브라우저가 열림 → Firebase 프로젝트 권한이 있는 구글 계정으로 로그인
firebase use                 ← 'iline-edu-support' 가 보이면 끝
```
`firebase use` 에서 프로젝트 이름이 다르게 나오면(만들 때 뒤에 숫자가 붙었을 수
있음) `.firebaserc` 의 값을 실제 ID 로 고치고 커밋하세요. 실제 ID 는 Firebase
콘솔 → 프로젝트 설정 → **프로젝트 ID** 에 있습니다.

> 이 로그인은 **본인 구글 계정**으로 하는 것이라 키 파일이 없습니다. 이어받는
> 사람은 자기 PC 에서 자기 계정으로 한 번 로그인하면 되고, 그 계정이 프로젝트에
> **편집자 이상**으로 초대돼 있어야 합니다. `firebase.json` · `.firebaserc` 는
> 저장소에 있으니 따로 설정할 것은 없습니다.

⚠️ **규칙과 코드를 함께 고쳤다면 규칙을 먼저** 올리세요.
반대로 하면 새 코드가 옛 규칙에 막혀 전부 실패합니다. 순서:
`npm run rules` → `git push`.

콘솔에 붙여넣는 옛 방법은 `01-firebase-데이터베이스.md` §6 에 **예비용**으로
남겨 두었습니다 — 도구가 안 될 때만.

### 시험 데이터 정리는 **목록부터**

```
node scripts/reset-test-data.mjs "키경로"
```

아무것도 지우지 않고 **목록만** 보여줍니다. 사라질 계정을 눈으로 확인한 뒤
`--delete` 를 붙이세요. 옵션은 **지우는 범위를 좁히기만** 합니다.

- 한 사람의 신청 기록만 → `--only 이메일 --keep-accounts --delete`
- 전체 청소 → `--delete` (담당자는 자동으로 남습니다)

### 담당자를 늘리려면 **두 곳**을 고쳐야 합니다

- Firestore 콘솔에서 `role: staff` — 화면 권한
- `node scripts/grant-staff.mjs "키경로" 이메일` — 파일 열람 권한

하나만 하면 **반쪽 담당자**가 됩니다.

> 🔒 서비스 계정 키는 **프로젝트 전체를 마음대로 할 수 있는 마스터키**입니다.
> 저장소 밖에 두시고, 채팅·메일에 붙여 넣지 마세요. 새 담당자에게
> **건네주면 안 됩니다** — 키를 가진 사람이 대신 실행해 주세요.

## 2. 배포

### 커밋 전에는 `git status` 부터

**새로 생긴 폴더가 빠지는 사고**가 실제로 있었습니다(09-08).
`git commit -am` 은 **이미 추적 중인 파일만** 올려서, 새 폴더가 통째로 빠진 채
push 되었고 Vercel 빌드가 깨졌습니다.

```
git status        ← 새 파일이 다 보이는지 눈으로 확인
git add -A        ← 새 파일까지 포함
```

### 배포 전에 미리 확인

Vercel 은 **저장소에 있는 모든 파일**을 검사합니다. `npm run dev` 만 돌리면
안 걸리던 것이 배포에서 걸립니다. 큰 변경 뒤에는 한 번 돌려보세요.

```
npm run build
```

여기서 통과하면 Vercel 에서도 대체로 통과합니다.

### 배포가 실패하면 **로그부터**

Vercel → 빨간 **Error** 배포 클릭 → **Build Logs** →
`Error:` 또는 `Failed to compile` 이 있는 줄과 그 앞뒤 몇 줄.

**추측보다 이 다섯 줄이 빠릅니다.** 09-08 에 이걸로 한 번에 원인을 찾았습니다.

### 시험 결과가 이상하면 **어느 버전인지부터**

"PC 는 되는데 휴대폰은 안 된다"의 정체가 기기 차이가 아니라 **push 전후
차이**였던 적이 있습니다. 배포 후에는 **새 코드가 올라갔는지** 눈에 보이는
변화로 먼저 확인하세요.

### 파일은 두고 깃에서만 빼기

```
git rm -r --cached "폴더이름"
```

PC 의 파일은 **그대로 두고** 저장소에서만 제외합니다.
`Claude outputs` 폴더를 뺄 때 썼습니다(09-08).

## 3. 간단한 팁

### 한글 파일 이름이 숫자로 보일 때

`git status` 에서 `"docs/1-\354\232\264\354\230\201/..."` 처럼 나오는 것은
**깨진 게 아니라** 깃이 한글을 이스케이프해서 보여주는 것입니다.
파일도 커밋도 멀쩡합니다.

```
git config core.quotepath false
```

이 저장소에만 적용됩니다. 이후로는 `docs/1-운영/02-화면-지도.md` 로 보입니다.

### 경로에 공백이나 한글이 있으면 큰따옴표

```
node scripts/reset-test-data.mjs "D:\my keys\서비스계정.json"
```

안 감싸면 공백에서 잘려 "파일을 못 찾겠다"가 됩니다.

### 그 폴더에서 터미널 열기

파일 탐색기에서 폴더를 연 다음 **주소창에 `cmd` 입력 후 Enter**.
`cd` 를 길게 칠 필요가 없습니다.

### 휴대폰 화면은 브라우저 안에서 확인합니다

로컬(`npm run dev`)에서도 됩니다. 크롬에서 **F12** → 왼쪽 위의 **휴대폰·태블릿
아이콘**(또는 `Ctrl+Shift+M`) → 위쪽 기기 목록에서 iPhone 등을 고릅니다.
가로 폭을 직접 끌어 줄여도 됩니다 — 이 사이트는 **768px 아래**에서 휴대폰
배치로 바뀝니다(격자 → 하루씩 보기 등). 실제 기기와 글자 크기·터치감은
다르니, **배포 뒤 진짜 휴대폰으로 한 번 더** 보는 것이 맞습니다.

### 자주 쓰는 명령 한눈에

| 무엇 | 명령 |
|---|---|
| 사이트 띄우기 | `npm run dev` → http://localhost:3000 |
| 배포 전 점검 | `npm run build` |
| 타입만 빠르게 확인 | `npm run typecheck` |
| 시험 데이터 **보기** | `node scripts/reset-test-data.mjs "키경로"` |
| 한 사람 신청만 비우기 | `… --only 이메일 --keep-accounts --delete` |
| 담당자 권한 주기 | `node scripts/grant-staff.mjs "키경로" 이메일` |
| 담당자 권한 회수 | `… --revoke` |
