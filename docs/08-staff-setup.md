# 담당자 권한 부여하기

> 담당자 화면(`/staff`)은 **아무에게도 열려 있지 않은 상태로 시작합니다.** 의도된 초기값입니다.
> 권한을 준 계정에만 헤더에 "신청 관리" 메뉴가 나타납니다.

## 권한이 두 종류입니다 — 왜 나뉘어 있나

| | 무엇을 할 수 있나 | 어디에 설정하나 | 난이도 |
|---|---|---|---|
| **① Firestore 담당자** | 신청 목록 조회, **상태 변경**, 사유 입력 | 콘솔에서 필드 하나 | 쉬움 |
| **② Storage 담당자** | 신청자가 올린 **첨부 파일 열람** | Custom Claims (스크립트 필요) | 번거로움 |

나뉜 이유는 **Storage 보안 규칙이 Firestore 를 읽지 못하기 때문**입니다.
"이 사람이 담당자인가"를 Storage 쪽에서는 알 방법이 없어서, 로그인 토큰에
직접 표시(Custom Claims)를 심어야 합니다.

**①만 해도 상태 관리는 됩니다.** ②는 첨부 파일을 열어야 할 때 하시면 됩니다.

---

## ① Firestore 담당자 — 지금 바로

1. Firebase 콘솔 → **Firestore Database** → `support_users`
2. 담당자로 지정할 **회원 문서**를 엽니다 (문서 ID = 그 사람의 uid)
3. `role` 필드를 찾아 값을 **`applicant` → `staff`** 로 바꿉니다
4. 그 계정에서 **새로고침** → 헤더에 **"신청 관리"** 가 나타납니다

> 필드를 새로 만들 필요는 없습니다. 회원가입 때 `role: "applicant"` 로 이미 들어가 있습니다.
> 값만 바꾸세요. 유형은 `string` 그대로입니다.

### 되돌리기

`staff` → `applicant` 로 바꾸면 즉시 회수됩니다. **인수인계·퇴사 시 반드시 되돌리세요.**

## ② Storage 담당자 — 첨부 파일을 열어야 할 때

담당자 화면에서 파일 버튼을 눌렀는데 열리지 않으면 이 설정이 빠진 것입니다.

### 준비물

Firebase **서비스 계정 키** 파일이 필요합니다.

1. 콘솔 → ⚙️ **프로젝트 설정** → **서비스 계정** 탭
2. **새 비공개 키 생성** → JSON 파일이 내려받아집니다

> 🔒 **이 파일은 프로젝트 전체를 마음대로 할 수 있는 마스터키입니다.**
> - **Git에 커밋하지 마세요.** 프로젝트 폴더 안에 두지 마시고, 예를 들어 `D:\keys\` 처럼 밖에 두세요
> - 채팅·메일·메신저로 보내지 마세요. 저에게도 보내실 필요 없습니다
> - 작업이 끝나면 콘솔에서 그 키를 **삭제**하셔도 됩니다 (같은 화면에서 가능)

### 실행

프로젝트 폴더에서:

```
node scripts/grant-staff.mjs D:\keys\서비스계정.json 담당자이메일@example.com
```

성공하면 이렇게 나옵니다.

```
✅ 담당자 권한을 부여했습니다: 담당자이메일@example.com
   해당 계정은 다시 로그인해야 적용됩니다.
```

### ⚠️ 다시 로그인해야 적용됩니다

Custom Claims 는 **로그인 토큰에 심기는 값**이라, 이미 로그인해 있는 사람에게는
바로 반영되지 않습니다. **로그아웃 후 다시 로그인**하셔야 합니다.

### 회수

```
node scripts/grant-staff.mjs D:\keys\서비스계정.json 담당자이메일@example.com --revoke
```

## ③ 구글 시트·드라이브 접근은 **또 별개**입니다

여기서 오해가 자주 생깁니다.

| | 무엇을 판단하나 | 어디서 관리 |
|---|---|---|
| ① Firestore `role: staff` | 사이트의 신청 관리 화면 | Firestore |
| ② Custom Claims | 사이트에서 남의 첨부 열람 | 스크립트 |
| **③ 구글 공유** | **시트·드라이브를 여는 것** | 구글 드라이브 |

**①②를 줘도 시트는 안 보입니다.** 반대로 ③만 있고 ①②가 없으면
시트는 보이는데 사이트에서는 아무것도 못 합니다.

서비스 계정을 시트·드라이브에 초대한 것은 **우리 서버가 쓰기 위한 것**이지,
담당자에게 권한을 나눠주는 것이 아닙니다. 서버는 파일을 만들 뿐입니다.

**담당자가 시트를 보려면 그 사람의 구글 계정을 따로 초대해야 합니다.**

- 스프레드시트 → 공유 → 담당자 구글 계정
- 공유 드라이브 → 멤버 관리 → 담당자 구글 계정

조직 계정으로 통일하면 관리가 훨씬 쉽습니다.

---

## 🔴 회수할 때 — 세 곳을 모두 되돌려야 합니다

```
① Firestore  role → applicant
② Claims     node scripts/grant-staff.mjs <키> <이메일> --revoke
③ 구글       시트·공유 드라이브에서 그 계정 제거   ← 가장 잘 잊습니다
```

**③을 빠뜨리면 사이트에서는 막혔는데 시트로는 학생 개인정보를 계속 봅니다.**
사이트에서 막았으니 끝났다고 생각하기 쉬운데, 구글 쪽 권한은 그대로 살아 있습니다.

---

## 운영 시 지켜야 할 것

- **담당자는 최소 인원으로.** 담당자는 모든 신청자의 개인정보를 볼 수 있습니다
- **인수인계 시 즉시 회수** — ①②③ **셋 다** 되돌려야 합니다 (위 절차 참고)
- 담당자 지정·회수 이력을 별도로 기록해 두세요 (감사 대응)
