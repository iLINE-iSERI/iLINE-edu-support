# 구글 시트·드라이브 반출 범위 (확정)

> 어떤 정보를 외부(구글 스프레드시트·공유 드라이브)로 내보낼지 정한 문서입니다.
> **여기 없는 항목은 내보내지 않습니다.** 코드에서 시트 열을 늘릴 때 이 문서를 먼저 고칩니다.

| 열 | 출처 | 비고 |

| 프로그램명 | 프로그램 | |
| 신청 일시 | 시스템 | |
| **이름** | 회원 정보 | |

| **학년** | 회원 정보 | |
| **연락처** | 회원 정보 | |
| **이메일** | 회원 정보 | 로그인 계정 |
| **개인정보 수집·이용 동의** | 동의 이력 | **O / X** |
| **초상권 활용 동의** | 동의 이력 | **O / X** |
| 상태 | 신청서 | 참고용 사본 — 원본은 사이트 |
| 증빙 폴더 | 드라이브 링크 | 아래 참고 |

**동의 여부를 O/X로 내보내는 이유**
초상권 동의는 **활동사진을 자료집·홈페이지에 쓸 수 있는지 판단하는 근거**입니다.
담당자가 사진을 고를 때 시트에서 바로 확인할 수 있어야 실수가 없습니다.
거부(X)도 반드시 표시합니다 — 기록이 없는 것과 거부한 것은 다릅니다.

## 2. 공유 드라이브에 올리는 파일

```
[공유 드라이브]
└─ 02_정산/
    └─ {신청번호}_{이름}/
        ├─ 영수증_01.jpg
        ├─ 영수증_02.jpg
        └─ (기타 지출 증빙)
```

**올리는 것**: 영수증 등 **지출 증빙 서류**

**올리지 않는 것**: 아래 §3 참고

> ⚠️ **확인 필요 (Q-3′)** — D-28에 따라 제출 시점에 **신청서 PDF**가 생성됩니다.
> §3의 민감 서류가 아니므로 드라이브에 둬도 무방하지만, **둘지 말지는 운영 판단**입니다.
> · 올린다면 → `01_신청/{신청번호}_{이름}.pdf`, 시트에 링크 열 하나 추가
> · 올리지 않는다면 → 담당자가 사이트에서 내려받아 인쇄
> 어느 쪽이든 **원본은 Storage**이고 드라이브 쪽은 사본입니다.

## 3. ⛔ 외부로 내보내지 않는 것

| 항목 | 이유 |
|---|---|
| **신분증 사본** | 민감정보. 외부 서비스로 내보내지 않음 |
| **통장 사본** | 〃 |
| 주소 등 그 밖의 신원 정보 | 애초에 수집하지 않음 |
| 비밀번호 | 시스템도 원문을 보관하지 않음 (Firebase가 해시로 관리) |

이런 파일이 **필요해지는 경우**에도 **Firebase Storage 안에만** 두고,
담당자는 사이트 안의 열람 화면에서 확인합니다. 드라이브로 복사하지 않습니다.

---

## 4. ⚠️ 이 결정으로 생긴 확인 사항

### 4-1. 신분증을 수집할 필요가 있는가?

대상이 **교원양성기관 재학생**이고 **학번·전공·학년**을 받고 있습니다.
자격 확인이 학번으로 되는 상황이라면 **신분증은 받지 않는 편이 낫습니다.**

- 개인정보는 적게 받을수록 관리 부담과 사고 위험이 줄어듭니다
- 받는 순간 보관·파기·접근통제 의무가 따라붙습니다
- 안 받으면 §3의 열람 화면도 만들 필요가 없습니다

→ **확인 필요**: 신분증을 정말 받아야 합니까? 받는다면 무엇을 확인하기 위해서입니까?

### 4-2. 정산 지급에 계좌 정보가 필요한가?

활동비를 계좌로 지급한다면 계좌번호나 통장 사본이 필요합니다. 이건 민감정보라
드라이브로 내보내지 않고 사이트 안에서만 다뤄야 합니다.

→ **확인 필요**: 계좌 정보를 **사이트에서 받습니까**, 아니면 별도 서류로 제출받습니까?
   사이트에서 받는다면 담당자 열람 화면이 필요합니다.

### 4-3. 담당자 열람 화면이 필요해질 수 있음

§3에 해당하는 파일(신분증·통장사본)을 **하나라도 받는다면**, 담당자가 볼 방법이
드라이브가 아니라 **사이트 안의 화면**이어야 합니다. 4-1과 4-2가 모두 "받지 않음"
이면 이 화면은 만들지 않아도 됩니다.

## 5. 운영 시 지켜야 할 것

- 스프레드시트 **공유 설정은 "제한됨"** — 링크 있는 사람 공유 금지, 지정 계정만
- 공유 드라이브 **외부 공유 차단** (관리 콘솔에서 설정)
- 멤버 추가·제거 절차 문서화 — **인수인계·퇴사 시 즉시 제거**
- 보유기간 만료 시 **Storage와 드라이브 두 곳 모두** 파기
