## 🔴 A. Firebase 보안 규칙 — 가장 주의가 필요함

운영 중인 그뤠잇과 **같은 Firebase 프로젝트**를 공유합니다(D-8).
규칙을 잘못 건드리면 **그뤠잇이 즉시 멈춥니다.**

### A-1. 적용 전

- [ ] **기존 규칙 백업** — Firebase 콘솔 `Firestore > 규칙`, `Storage > 규칙`의 현재 내용을 파일로 저장
- [ ] **트래픽이 적은 시간대 선택** — 야간·주말. 수업 시간대는 피할 것
- [ ] 병합본 확인 — `firebase-deploy/firestore.rules`, `firebase-deploy/storage.rules`
      (창의재단 레포의 `firestore.rules` / `storage.rules` 는 **창의재단 부분만** 담은 발췌본입니다.
       그것을 콘솔에 붙여넣으면 그뤠잇 규칙이 사라집니다)

### A-2. 적용

- [ ] Firestore 규칙 게시
- [ ] Storage 규칙 게시

### A-3. 적용 직후 회귀 확인 (그뤠잇이 멀쩡한지)

- [ ] 그뤠잇 로그인 → **강의 목록**이 보이는가
- [ ] **공지사항 / 자료실**이 열리는가
- [ ] **관리자 화면**(`/admin/courses` 등)이 동작하는가
- [ ] **비로그인 상태**에서 메인의 카테고리가 보이는가 (`categories` 는 공개 읽기)
- [ ] 수료증·포인트 등 로그인 사용자 기능이 정상인가

> 하나라도 이상하면 **즉시 백업본으로 되돌리세요.** 원인 분석은 그다음입니다.

### A-4. 이후

- [ ] **담당자 계정에 Custom Claims `supportStaff: true` 부여** (Phase 5)
      — 이게 없으면 담당자 전용 기능이 아무에게도 열리지 않습니다. 의도된 초기 상태입니다

      (콘솔에서만 고치면 변경 이력이 남지 않습니다)

- [ ] **`.env.local.txt` 를 Git 추적에서 제거**

      `.gitignore` 에 `.env*.txt` 추가. *(값이 전부 `NEXT_PUBLIC_*` 공개 설계값이라 유출 사고는 아니지만,
      앞으로 서비스 계정 키를 같은 파일에 적으면 그대로 커밋됩니다)*

- [ ] **`sitemap.xml` · `robots.txt` 신규 작성** — 현재 둘 다 없음(404 확인)
- [ ] 루트 페이지 교체 + `href="/"` **7곳**을 `/home` 으로 (D-21, 파일 9개)
