# 구글 시트·드라이브 연동 준비

> 신청이 제출되면 **스프레드시트에 한 줄이 쌓이고**, 신청서 PDF와 첨부가
> **공유 드라이브 폴더**에 올라갑니다. 담당자는 시트에서 링크를 눌러 바로 엽니다.
>
> 반출 범위는 `docs/05-sheet-drive-scope.md` 에서 확정한 대로입니다.
> **신분증·통장 사본 같은 민감 서류는 나가지 않습니다.**

---

## 0. 왜 서버가 필요한가

구글 시트에 쓰려면 **서비스 계정 키**가 필요한데, 이 키는 브라우저에 둘 수 없습니다.
넣는 순간 누구나 열어볼 수 있고, 그 키 하나로 드라이브 전체가 열립니다.

그래서 이 기능만 **서버(Vercel)에서 돕니다.** 사이트의 나머지는 그대로입니다.

```
학생이 제출
   ↓ (브라우저 → Firebase)  신청서·PDF·첨부 저장   ← 원본은 언제나 여기
   ↓ (브라우저 → 우리 서버)  "이 신청건 동기화해 줘"
   ↓ (서버 → 구글)          시트에 한 줄 + 드라이브에 파일 사본
```

**동기화가 실패해도 신청은 이미 완료된 상태입니다.** 시트는 사본이지 원본이 아닙니다.

## 1. 공유 드라이브 만들기 (조직 계정 사용)

**조직(Google Workspace) 계정으로 하세요.** 개인 Gmail 계정에는 공유 드라이브 기능이
아예 없습니다.

그리고 개인 드라이브(내 드라이브)로는 안 됩니다. 서비스 계정은 **저장 용량이 없어서**
개인 드라이브에 파일을 올리지 못합니다. 공유 드라이브는 **드라이브가 파일을 소유**하므로
가능합니다.

### 만들기

1. **조직 계정으로** [drive.google.com](https://drive.google.com) 접속
2. 좌측 **공유 드라이브** → **새로 만들기**
   - 이 메뉴가 안 보이면 개인 계정으로 로그인되어 있거나, 조직 정책으로 생성이
     제한된 것입니다. 후자면 전산 담당자에게 요청해야 합니다
3. 이름: `교원양성지원사업` (예시)
4. 안에 폴더를 만듭니다

```
[공유 드라이브] 교원양성지원사업
├─ 01_신청/     ← 신청서 PDF (D-30)
└─ 02_정산/     ← 영수증 등 증빙
```

5. **`01_신청` 폴더를 열고 주소창의 ID를 복사**해 둡니다

```
https://drive.google.com/drive/folders/1AbCdEfGhIjKlMnOpQrStUv
                                        └──────── 이 부분 ────────┘
```

### 만드는 사람 = 관리자

공유 드라이브를 만든 계정이 관리자가 됩니다. **개인 담당자 계정 하나로만 만들면
그 사람이 떠날 때 곤란합니다.** 만든 직후 **다른 담당자 한 명 이상을 관리자로
추가**해 두세요.

### 조직 계정이라 좋은 점

- 사업 종료 후 인수인계가 계정 이동 없이 됩니다 (드라이브가 파일을 소유)
- 관리 콘솔에서 **외부 공유를 조직 차원에서 차단**할 수 있습니다
- 담당자가 바뀌어도 파일이 사라지지 않습니다

## 2. 스프레드시트 만들기

1. **공유 드라이브 안에** 새 스프레드시트 생성 (내 드라이브 아님)
2. 이름: `신청 현황`
3. 주소창의 ID를 복사해 둡니다

```
https://docs.google.com/spreadsheets/d/1XyZ.../edit
                                      └── 이 부분 ──┘
```

**첫 줄(머리글)은 만들지 않아도 됩니다.** 첫 동기화 때 코드가 알아서 넣습니다.

## 4. 서비스 계정을 시트·폴더에 초대

여기가 가장 많이 빠뜨리는 단계입니다. **API를 켜는 것과 권한을 주는 것은 다릅니다.**

서비스 계정 이메일은 키 파일(JSON) 안의 `client_email` 값입니다.
`firebase-adminsdk-xxxxx@iline-edu-support.iam.gserviceaccount.com` 같은 형태입니다.

1. **스프레드시트** → 우측 상단 **공유** → 그 이메일 추가 → 권한 **편집자**
2. **공유 드라이브** → 멤버 관리 → 그 이메일 추가 → 권한 **콘텐츠 관리자** 이상

> 알림 메일 보내기는 꺼도 됩니다. 서비스 계정은 메일을 읽지 않습니다.

### ⚠️ 조직 계정에서 자주 막히는 지점

**서비스 계정은 조직 입장에서 "외부 사용자"입니다.** 도메인이
`@iline-edu-support.iam.gserviceaccount.com` 이라 조직 도메인과 다르기 때문입니다.

그래서 관리 콘솔에서 **외부 공유를 전면 차단**해 두면, 이 초대 자체가 거부됩니다.
*"조직 외부 사용자와 공유할 수 없습니다"* 같은 메시지가 뜹니다.

**해결 방법** (전산 담당자에게 요청)

| 방법 | 내용 |
|---|---|
| **허용 목록(권장)** | 외부 공유는 차단하되, `*.iam.gserviceaccount.com` 또는 해당 이메일만 예외 허용 |
| 일시 허용 | 초대할 때만 외부 공유를 잠깐 열고, 끝나면 다시 닫기 |

두 번째 방법도 **한 번 맺어진 권한은 유지**되므로 실무상 문제없습니다.
다만 나중에 다른 서비스 계정을 추가할 때 같은 작업을 반복해야 합니다.

> **"외부 공유 차단"의 원래 목적은 지켜집니다.** 학생 개인정보가 조직 밖으로
> 나가지 않게 하려는 것인데, 서비스 계정은 **우리 사이트의 서버**이지
> 제3자가 아닙니다. 전산 담당자께 이렇게 설명하시면 됩니다.

## 5. Vercel 환경변수 5개

**Vercel → 프로젝트 → Settings → Environment Variables**

키 파일(JSON)을 열어 값을 옮깁니다.

| Key | 어디서 | 비고 |
|---|---|---|
| `FIREBASE_PROJECT_ID` | JSON의 `project_id` | |
| `FIREBASE_CLIENT_EMAIL` | JSON의 `client_email` | |
| `FIREBASE_PRIVATE_KEY` | JSON의 `private_key` | **아래 주의사항** |
| `SHEET_ID` | 2번에서 복사한 ID | |
| `DRIVE_FOLDER_ID` | 1번에서 복사한 `01_신청` 폴더 ID | |

**환경(Environments)은 `Production and Preview`.**

### ⚠️ `FIREBASE_PRIVATE_KEY` 주의

JSON 안에서 이렇게 생겼습니다.

```
"private_key": "-----BEGIN PRIVATE KEY-----\nMIIEvQIB...\n-----END PRIVATE KEY-----\n"
```

**바깥 큰따옴표만 빼고, `\n` 은 그대로 둔 채** 통째로 붙여넣으세요.
코드가 `\n` 을 실제 줄바꿈으로 되돌립니다.

> 이 값들은 이름 앞에 `NEXT_PUBLIC_` 이 **없습니다.** 그래서 브라우저로 내려가지
> 않고 서버에서만 읽힙니다. 이름을 바꾸지 마세요.

### 🔒 이 값은 채팅·메일로 보내지 마세요

저에게도 보내실 필요 없습니다. Vercel 화면에 직접 붙여넣으시면 됩니다.

## 6. 로컬에서도 시험하려면

`.env.local` 에 같은 5개를 추가하시면 로컬에서도 동작합니다.
넣지 않으면 로컬에서는 동기화가 **조용히 건너뜁니다**(오류 아님).

## 7. 반영시키기 — Redeploy 인가 push 인가

환경변수를 저장하는 것만으로는 **이미 떠 있는 배포에 반영되지 않습니다.**
다만 무엇을 해야 하는지는 상황에 따라 다릅니다.

| 상황 | 할 일 |
|---|---|
| **코드도 함께 바뀜** (연동 기능을 처음 붙일 때) | **`git push`** — 새 코드 + 새 환경변수로 자동 배포됩니다 |
| 코드는 그대로, 환경변수만 수정 | Deployments → **⋯ → Redeploy** |

> ⚠️ **Redeploy 는 "선택한 배포의 소스 코드를 그대로 다시 빌드"** 합니다.
> 코드를 아직 push 하지 않은 채 누르면 **옛 코드가 새 환경변수로 배포**됩니다.
> API 경로가 아예 없으니 시트에 아무것도 안 올라가는데, 설정이 없을 때처럼
> 조용히 건너뛰어서 원인을 찾기 어렵습니다.
> *(09-05: 실제로 이 순서를 헷갈릴 뻔했음)*

> Redeploy 창의 **`Use existing Build Cache` 는 체크하지 마세요.**
> 라이브러리가 추가된 뒤에는 캐시가 옛 상태를 물고 있을 수 있습니다.

## 8. 확인

1. push(또는 Redeploy)가 끝날 때까지 1~2분
2. 시험 계정으로 신청서를 하나 제출
3. **스프레드시트에 줄이 생겼는지** (머리글도 자동으로 만들어집니다)
4. **드라이브 `01_신청` 에 PDF가 올라갔는지**
5. 시트의 링크를 눌러 열리는지

안 되면 **담당자 화면의 해당 신청 건**에 동기화 실패 사유가 표시됩니다.

## 자주 나는 문제

| 증상 | 원인 |
|---|---|
| `The caller does not have permission` | 4번(서비스 계정 초대)을 안 했거나 권한이 보기 전용 |
| 초대 자체가 거부됨 | 조직의 **외부 공유 차단** 정책. 4번의 "조직 계정에서 자주 막히는 지점" 참고 |
| `File not found: <ID>` | 시트·폴더 ID 오타이거나, 서비스 계정에게 그 파일이 보이지 않음(=초대 안 됨) |
| `Service Accounts do not have storage quota` | **개인 드라이브**에 올리려 한 것. 공유 드라이브여야 합니다 |
| `API has not been used in project ...` | 3번(API 사용 설정)을 안 함 |
| `error:1E08010C:DECODER routines` | `FIREBASE_PRIVATE_KEY` 붙여넣기가 깨짐. `\n` 을 지우거나 줄바꿈이 들어간 경우 |
| 아무 일도 안 일어남 | 환경변수가 없어 건너뛴 것. Redeploy 했는지 확인 |
