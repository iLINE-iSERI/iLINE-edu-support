# 지원사업 전용 Firebase 프로젝트 만들기 (D-25)

> iLINE과 **별도의 Firebase 프로젝트**를 씁니다.
> 이 문서를 위에서부터 그대로 따라 하시면 됩니다. 15~20분 정도 걸립니다.
> 확정일: 2026-09-04

**왜 나눴나** — 규칙·권한·할당량이 프로젝트 단위라서, 같이 쓰면
(1) 지원사업 규칙을 고칠 때마다 iLINE이 위험해지고,
(2) 담당자에게 콘솔 권한을 주면 iLINE 데이터까지 보이며,
(3) 사업 종료 시 개인정보 파기를 증명하기 어렵기 때문입니다.

---

## 0. 시작 전에

- **iLINE 프로젝트는 이 문서에서 한 번도 건드리지 않습니다.** 실수로 열었다면 그냥 닫으세요.
- Google 계정은 **사업 담당 계정**으로 하시는 게 좋습니다. 개인 계정으로 만들면 인수인계가 번거롭습니다.
- 결제수단(카드)이 필요합니다. 아래 §2 참고.

---

## 1. 프로젝트 만들기

1. [console.firebase.google.com](https://console.firebase.google.com) 접속
2. **프로젝트 만들기**
3. 이름: **`iline-edu-support`** (권장). 프로젝트 ID가 이미 쓰이고 있으면 뒤에 숫자가 붙습니다 — 그대로 두셔도 됩니다
4. **Google 애널리틱스는 사용 안 함** — 필요 없고, 켜면 개인정보 처리 항목이 하나 늘어납니다
5. **프로젝트 만들기** → 30초쯤 기다립니다

---

## 2. Blaze(종량제) 요금제로 올리기

Storage 기본 버킷을 만들려면 필요합니다. 2024년 9월 이후 만들어진 프로젝트의 공통 조건입니다.

1. 좌측 하단 **요금제 업그레이드** (또는 ⚙️ → 사용량 및 결제)
2. **Blaze** 선택 → 결제 계정 연결

### 💰 요금이 걱정되실 텐데

Blaze 는 "무료 할당량을 넘긴 만큼만 청구"입니다. 무료 할당량은 그대로 남아 있습니다.

| 항목 | 무료 할당량 | 이 사업의 예상 규모 |
|---|---|---|
| Storage 저장 | 5GB | 영수증 사진 수천 장 수준 |
| Firestore 읽기 | 5만 건/일 | 신청자 수백 명이면 한참 남습니다 |
| 인증 | 사실상 무제한 | |

**실제 청구액은 0원일 가능성이 높습니다.** 다만 0원이 보장되는 건 아니므로 아래를 꼭 하세요.

### ⚠️ 예산 알림 설정 — 건너뛰지 마세요

1. ⚙️ → **사용량 및 결제** → **세부정보 및 설정** → **예산 및 알림**
2. 예산 만들기 → 금액 **1,000원** 정도
3. 임계값 50% / 90% / 100% 에서 **이메일 알림**

이렇게 해두면 뭔가 잘못돼서 요금이 발생하기 시작할 때 **몇백 원 단위에서 바로 알게 됩니다.**
(예산은 자동 차단이 아니라 알림입니다. 알림이 오면 그때 조치하시면 됩니다.)

## 3. 로그인 방법 켜기

1. 좌측 **빌드 > Authentication** → **시작하기**
2. **Sign-in method** 탭
3. **이메일/비밀번호** → 사용 설정 → 저장
   - 아래 "이메일 링크(비밀번호 없는 로그인)"는 **끕니다**
4. **Google** → 사용 설정 → **프로젝트 지원 이메일**을 담당 계정으로 선택 → 저장

---

## 4. Firestore 만들기

1. 좌측 **빌드 > Firestore Database** → **데이터베이스 만들기**
2. 아래 표대로 고릅니다

| 항목 | 값 | 설명 |
|---|---|---|
| **버전(Edition)** | **Standard** | Enterprise는 MongoDB 호환용 별도 상품입니다. 요금 체계도 API도 달라서 지금 코드가 동작하지 않습니다 |
| **데이터베이스 ID** | **`(default)`** ← 기본값 그대로 | 코드가 `getFirestore()` 로 기본 DB를 부릅니다. 다른 ID면 코드에서 매번 지정해야 합니다 |
| **위치** | **`asia-northeast3 (Seoul)`** | 이것만 바꾸면 됩니다 |
| **모드** | **프로덕션 모드에서 시작** | 테스트 모드는 30일 뒤 전부 잠깁니다 |

> ⚠️ **버전 · 데이터베이스 ID · 위치는 나중에 바꿀 수 없습니다.**
> 잘못 만들면 데이터베이스를 지우고 다시 만들어야 합니다. 이 화면만 한 번 더 확인하세요.
> 요약하면 **위치만 서울로 바꾸고 나머지는 손대지 않으면 됩니다.**

---

## 5. Storage 시작

1. 좌측 **빌드 > Storage** → **시작하기**
2. "기본 버킷 설정" 화면에서 **⚠️ 위쪽 "무료 위치"를 고르지 마세요.**

   | 선택 | 값 |
   |---|---|
   | 라디오 | **모든 위치** ← 아래쪽 |
   | 위치 | **`asia-northeast3` (서울)** |
   | 액세스 빈도 | **Standard(표준)** |

3. 다음 단계(보안 규칙) → **프로덕션 모드**. 규칙은 §6에서 통째로 교체합니다

### 왜 무료 위치를 쓰지 않는가

"무료 위치"는 **미국 리전만** 제공합니다. 이 버킷에는 **학생의 영수증·증빙 서류**가 올라갑니다.

| | 미국(무료) | 서울 |
|---|---|---|
| **개인정보 국외 이전** | **발생** — 처리방침에 이전 국가·항목·시점을 별도 고지해야 하고 행정 검토 대상이 됨 | 없음 |
| Firestore 위치와 | 갈림 | 일치 |
| 휴대폰 업로드 속도 | 느림 | 빠름 |
| 저장 요금 | 5GB 무료 | **월 수백 원 수준** (GB당 월 30~40원대) |

공공 재정지원사업에서 "학생 개인정보를 미국에 보관한다"를 문서에 적는 것보다,
**월 200원 안팎을 쓰는 편이 낫다**고 판단했습니다. §2에서 건 예산 알림이 안전망입니다.

> **위치는 나중에 바꿀 수 없습니다.**
> 이 선택은 `app/privacy/page.tsx`(개인정보 처리방침)의 국외이전 항목 필요 여부와 직결됩니다.

---

## 6. 보안 규칙 붙여넣기

이제 **통째로 덮어써도 안전합니다.** 이 프로젝트에는 iLINE 규칙이 없습니다.

1. **Firestore Database → 규칙** 탭
   → 레포의 **`firestore.rules`** 파일 내용을 **전체 복사해서 전체 교체** → **게시**
2. **Storage → 규칙** 탭
   → 레포의 **`storage.rules`** 전체 교체 → **게시**

> 게시 직후 화면에 "규칙이 게시되었습니다"가 뜨면 끝입니다.
> 예전 문서에 있던 *병합본(`firebase-deploy/`)* 은 **더 이상 쓰지 않습니다.**

---

## 7. 웹 앱 등록 → 환경변수

1. ⚙️ **프로젝트 설정** → **일반** 탭 → 맨 아래 **내 앱**
2. **웹(`</>`)** 아이콘 클릭
3. 앱 닉네임: `iline-edu-support-web` → **Firebase 호스팅은 체크하지 않습니다** (Vercel을 씁니다)
4. 나오는 `firebaseConfig` 값을 `.env.local` 에 옮겨 적습니다 → **`docs/03-env-local.md`** 참고

---

## 8. 승인된 도메인

배포 전이라도 지금 넣어두면 나중에 사고가 안 납니다.

**Authentication → 설정 → 승인된 도메인**

**지금 추가할 것: `support.iline.or.kr` 하나입니다.**

- `localhost` — 이미 들어 있습니다. 로컬 개발은 그대로 됩니다
- `...firebaseapp.com` / `...web.app` — Firebase 호스팅 기본값. 건드리지 않습니다
- **Vercel 주소** — 프로젝트를 만들어야 정확한 이름을 알 수 있으므로 **배포 단계에서** 추가합니다

> ⚠️ **와일드카드(`*.vercel.app`)는 받지 않습니다.** 도메인을 하나씩 정확히 적어야 합니다.
> Vercel 미리보기 주소는 배포마다 달라져서 이 목록으로는 감당이 되지 않습니다.
> 미리보기에서 로그인 테스트가 필요하면 별도 방법이 필요합니다.

> 이걸 빠뜨리면 **배포 후 로그인이 통째로 실패합니다.** 가장 흔한 배포 사고입니다.

## 9. 확인

1. 개발 서버 재시작 (`Ctrl+C` 후 `npm run dev`)
2. 브라우저 콘솔(F12)에 **`[iLINE] Firebase 환경변수가 없습니다`** 경고가 없어야 합니다
3. **회원가입 → 2단계까지 완료** → Firestore 콘솔 `support_users` 에 문서가 생겼는지 확인
4. `docs/04-program-setup.md` 의 **샘플 프로그램 3벌**을 넣고 `/apply` 확인

컬렉션 이름에 `support_` 접두어를 그대로 유지해 두었기 때문에, 나중에 다시
iLINE 프로젝트로 합쳐야 하더라도 **이름 충돌 없이 데이터를 옮길 수 있습니다.**
분리를 되돌릴 수 없는 결정으로 만들지 않으려고 남겨둔 장치입니다.
